# Лабораторная 0. Рабочее окружение: терминал, Node.js, отладка, git

**Цель:** освоить инструменты, без которых не обойтись ни в одной следующей
лабораторной. Вы научитесь ходить по папкам в терминале, запускать
JavaScript-файлы через Node.js, читать сообщения об ошибках, искать ошибку
отладчиком и сохранять свою работу в git.

**Для кого:** вы знаете синтаксис JavaScript и решали задачи, но писали код
в браузере или в онлайн-редакторе и почти не работали в терминале.

**Понадобится:** компьютер с Windows, macOS или Linux и доступ в интернет
для установки программ.

**Примерное время:** 3–4 часа, два занятия.

## Как устроена эта лабораторная

Каждая тема идёт в одном и том же порядке:

1. **Зачем** — какую проблему решает инструмент.
2. **Разобранный пример** — делайте его вместе с текстом, шаг за шагом,

3. **Разминка** — несколько коротких заданий на 5–10 минут.

В конце — большие упражнения, раздел «Типичные ошибки» и контрольные вопросы.
Ответы на вопросы и разминки — в файле [answers.md](answers.md). Загляните

## Занятие 1. Терминал и Node.js

### Установка

1. **Node.js.** Скачайте версию LTS с [nodejs.org](https://nodejs.org/)
   и установите со стандартными настройками. Нужна версия 22.13 или новее,
   лучше 24.
2. **Редактор.** [Visual Studio Code](https://code.visualstudio.com/) — бесплатный,
   и в нём есть всё нужное: терминал и отладчик.
3. **Git.** В Windows — [Git for Windows](https://git-scm.com/download/win):
   вместе с ним установится терминал Git Bash. В macOS git предложат
   установить при первом вызове `git`. В Linux — через менеджер пакетов
   (`sudo apt install git`).

### Что такое терминал

**Зачем.** Терминал — это окно, где вы управляете компьютером текстовыми
командами вместо мыши. Программы для Node.js запускают именно отсюда,
и большинство инструментов разработчика (npm, git, тесты) — тоже консольные.

Программа, которая читает ваши команды и выполняет их, называется
**оболочкой** (shell). Их несколько:

| система | оболочка                                 | как открыть                             |
| ------- | ---------------------------------------- | --------------------------------------- |
| Windows | PowerShell, а также Git Bash (после git) | меню «Пуск» → «Терминал» или «Git Bash» |
| macOS   | zsh                                      | программа «Терминал»                    |
| Linux   | bash                                     | Ctrl+Alt+T или «Терминал» в меню        |
| любая   | терминал внутри VS Code                  | в VS Code: меню Terminal → New Terminal |

Команды в лабораторных написаны для bash: они же работают в zsh и Git Bash.
В PowerShell почти все простые команды тоже работают, отличия собраны
в таблице ниже.

Терминал показывает **приглашение** — строку, после которой вы печатаете
команду. Обычно в ней видна текущая папка:

```
atomskz@PC MINGW64 ~/projects
$ █
```

`$` (или `>` в PowerShell) — сам знак приглашения, его печатать не нужно.
Когда в лабораторной написано `node app.js`, это значит: наберите
`node app.js` и нажмите Enter.

### Папки и пути

У терминала всегда есть **текущая папка** — та, «в которой вы находитесь».
Команды по умолчанию работают с ней.

**Путь** — адрес файла или папки:

- **абсолютный** — от корня диска: `C:\Users\ann\projects\chat` в Windows,
  `/home/ann/projects/chat` в Linux, `/Users/ann/projects/chat` в macOS;
- **относительный** — от текущей папки: `chat/server.js` значит «папка `chat`
  внутри текущей, а в ней файл `server.js`»;
- `.` — текущая папка, `..` — папка уровнем выше, `~` — ваша домашняя папка.

В Windows части пути разделяет `\`, в Linux и macOS — `/`. Git Bash
и PowerShell понимают оба варианта, поэтому в лабораторных пишем `/`.

### Основные команды

| что сделать                     | bash, zsh, Git Bash                 | PowerShell          |
| ------------------------------- | ----------------------------------- | ------------------- |
| где я?                          | `pwd`                               | `pwd`               |
| что в папке?                    | `ls`, подробно `ls -la`             | `ls`                |
| перейти в папку                 | `cd projects`                       | `cd projects`       |
| на уровень выше                 | `cd ..`                             | `cd ..`             |
| в домашнюю папку                | `cd ~` или просто `cd`              | `cd ~`              |
| создать папку                   | `mkdir notes`                       | `mkdir notes`       |
| создать вложенные папки сразу   | `mkdir -p a/b/c`                    | `mkdir a/b/c`       |
| создать пустой файл             | `touch todo.txt`                    | `New-Item todo.txt` |
| показать содержимое файла       | `cat todo.txt`                      | `cat todo.txt`      |
| скопировать / переместить       | `cp a.txt b.txt` / `mv a.txt docs/` | то же самое         |
| удалить файл                    | `rm todo.txt`                       | `rm todo.txt`       |
| очистить экран                  | `clear`                             | `cls` или `clear`   |
| открыть текущую папку в VS Code | `code .`                            | `code .`            |

Команда `code` появляется после установки VS Code в Windows и Linux сама.
В macOS её включают один раз: в VS Code Cmd+Shift+P → «Shell Command:
Install 'code' command in PATH».

Три приёма, которые экономят часы:

- **Tab** дописывает имя файла или папки: наберите `cd pro` и нажмите Tab;
- **стрелка вверх** возвращает предыдущие команды;
- **Ctrl+C** прерывает команду, которая «зависла» или работает бесконечно.

Удаление через `rm` — **без корзины**. Файл пропадает сразу и насовсем.

### Разобранный пример: дерево папок

Повторяйте команды и сравнивайте вывод (имена в первой строке у вас будут свои):

```bash
cd ~                 # перейти в домашнюю папку
pwd                  # /c/Users/ann  (или /home/ann)
mkdir -p js-labs/sandbox-00
cd js-labs
ls                   # sandbox-00
cd sandbox-00
pwd                  # /c/Users/ann/js-labs/sandbox-00
touch notes.txt      # в PowerShell: New-Item notes.txt
ls                   # notes.txt
cd ../..             # на два уровня вверх — снова домашняя папка
pwd                  # /c/Users/ann
```

Что произошло: `mkdir -p` создал сразу две вложенные папки, `cd js-labs`
перешёл по **относительному** пути, а `cd ../..` поднялся на два уровня.

### Node.js: REPL и запуск файлов

**Зачем.** Node.js — программа, которая выполняет JavaScript вне браузера.
С ней можно писать серверы, консольные утилиты и всё, что делается
в этих лабораторных.

Проверьте установку:

```bash
node --version       # v24.19.0 или похожая версия
npm --version        # 11.x
```

**REPL** (Read-Eval-Print Loop) — режим, в котором Node.js выполняет
каждую строку сразу. Удобен, чтобы быстро что-то проверить:

```
$ node
Welcome to Node.js v24.19.0.
> 2 + 2
4
> const name = 'Ann'
undefined
> `Hello, ${name}`
'Hello, Ann'
> [3, 1, 2].sort()
[ 1, 2, 3 ]
> .exit
```

`undefined` после `const` — не ошибка: REPL печатает результат каждой
строки, а у объявления переменной результата нет. Выйти можно командой
`.exit` или двойным Ctrl+C.

**Файл.** Настоящие программы пишут в файлах и запускают командой
`node имя-файла.js`. Node.js ищет файл относительно **текущей папки**
терминала, поэтому сначала перейдите туда, где лежит файл.

```js
// hello.js
const name = process.argv[2] ?? 'world';
console.log(`Hello, ${name}!`);
```

```bash
node hello.js        # Hello, world!
node hello.js Ann    # Hello, Ann!
```

`process.argv` — массив слов командной строки. `process.argv[2]` — первое
слово после имени файла (подробно — в лабораторной 2). `??` подставляет
`'world'`, если слова нет (см. [шпаргалку](../js-cheatsheet.md)).

В браузере результат `console.log` виден в инструментах разработчика,
а здесь — прямо в терминале. `document`, `window` и `alert` в Node.js нет:
это части браузера, а не языка.

## Занятие 2. Ошибки, отладка и git

### Как читать сообщение об ошибке

**Зачем.** Ошибки будут всегда. Сообщение об ошибке — не приговор,
а подсказка, где и что сломалось. Самое полезное в нём — первые строки.

Вот что печатает Node.js, если вызвать переменную с опечаткой в имени:

```
C:\Users\ann\js-labs\sandbox-00\average.js:12        ← файл и строка
  return totl / numbers.length;                          ← сама строка
  ^                                                      ← место ошибки

ReferenceError: totl is not defined                      ← вид и текст ошибки
    at average (C:\...\average.js:12:3)                  ← стек вызовов: где случилось
    at Object.<anonymous> (C:\...\average.js:15:25)      ← ...и откуда туда пришли
    at Module._compile (node:internal/...)               ← внутренности Node.js — пропускаем
```

В Linux и macOS путь будет вида `/home/ann/js-labs/...`. В проектах
с `"type": "module"` (с лабораторной 1) путь начинается с `file:///`,
а внутренние строки Node.js называются иначе — читать их всё равно не нужно.

Как читать, по шагам:

1. **Вид и текст** (`ReferenceError: totl is not defined`) — что случилось.
2. **Первая строка стека** с вашим файлом (`average.js:12:3` — строка 12,
   символ 3) — где случилось. В VS Code по такой ссылке можно кликнуть
   с зажатым Ctrl.
3. **Следующие строки стека** — кто вызвал эту функцию. Строки с `node:internal`
   — код самого Node.js, их обычно пропускают.

Самые частые виды ошибок:

| ошибка           | что значит                                     | пример                                                   |
| ---------------- | ---------------------------------------------- | -------------------------------------------------------- |
| `SyntaxError`    | код написан неправильно, он даже не запустился | забыта скобка, `retrun` вместо `return`                  |
| `ReferenceError` | имя не объявлено                               | опечатка в имени переменной                              |
| `TypeError`      | значение не того типа                          | `null.length`, `undefined()` — вызов не функции          |
| `RangeError`     | значение вне допустимого диапазона             | бесконечная рекурсия: `Maximum call stack size exceeded` |

Хуже всего ошибки **без сообщения**: программа работает, но печатает
не то (`NaN`, `undefined`, `[object Object]`). Их ищут отладкой.

### Отладка: `console.log` и отладчик

**`console.log`** — самый простой способ: напечатать значение там,
где есть подозрение.

```js
console.log('total =', total); // несколько аргументов через запятую
console.log({ total, i }); // объект: сразу видно и имя, и значение
console.log(typeof total); // 'string' вместо 'number' — вот и ошибка
```

**Отладчик** позволяет остановить программу на нужной строке и посмотреть
все переменные, не дописывая `console.log`. В VS Code:

1. Откройте папку с файлом: File → Open Folder (или `code .` в терминале).
2. Кликните слева от номера строки — появится красная точка, **точка останова**.
3. Откройте терминал отладки: в панели терминала стрелка рядом с `+` →
   **JavaScript Debug Terminal**.
4. Запустите программу в этом терминале как обычно: `node average.js 5 4 3`.
   Программа остановится на точке останова, а слева появится панель
   **Variables** с текущими значениями переменных.
5. Управление: **F10** — выполнить строку и перейти к следующей,
   **F11** — зайти внутрь вызываемой функции, **F5** — продолжить
   до следующей точки останова, Shift+F5 — остановить.

Наведите мышь на переменную в коде — редактор покажет её значение.
Остановиться можно и из кода: строка `debugger;` работает как точка останова,
если программа запущена в терминале отладки.

### Git: история своей работы

**Зачем.** Git сохраняет «снимки» проекта — **коммиты**. С ним можно
посмотреть, что вы изменили, вернуть файл к рабочему состоянию, если
сломали, и отправить работу на проверку. Каждая следующая лабораторная
советует делать по коммиту.

Один раз после установки представьтесь git (эти данные попадут в каждый коммит):

```bash
git config --global user.name "Ann Smith"
git config --global user.email "ann@example.com"
```

Основной цикл:

```
изменили файлы ──► git status ──► git add ──► git commit ──► git log
   (рабочая папка)   (что изменилось)  (что войдёт в снимок)  (снимок)   (история)
```

| команда                      | что делает                                               |
| ---------------------------- | -------------------------------------------------------- |
| `git init`                   | превратить текущую папку в репозиторий (один раз)        |
| `git status`                 | какие файлы изменены, какие готовы к коммиту             |
| `git diff`                   | что именно изменилось в файлах (построчно)               |
| `git add файл` / `git add .` | добавить изменения в следующий коммит / добавить всё     |
| `git commit -m "текст"`      | сделать коммит с описанием                               |
| `git log --oneline`          | история коммитов, по строке на коммит                    |
| `git restore файл`           | отменить незакоммиченные изменения файла (без возврата!) |

Файл `.gitignore` перечисляет то, что git должен игнорировать. Например,
папку `node_modules/` (лабораторная 1).

### Разобранный пример: первые коммиты

Делайте этот пример в Git Bash (или в терминале macOS и Linux): в Windows
PowerShell 5.1 команда `echo ... > файл` записывает файл в кодировке UTF-16,
и git покажет его как двоичный. В PowerShell создайте файл в редакторе.

```bash
cd ~/js-labs/sandbox-00
git init                          # Initialized empty Git repository ...
echo "Buy milk" > notes.txt       # записать строку в файл
git status                        # Untracked files: notes.txt
git add notes.txt
git commit -m "Add notes"         # [master (root-commit) 1a2b3c4] Add notes
echo "Call mom" >> notes.txt      # >> дописывает в конец файла
git diff                          # +Call mom — добавленная строка
git commit -am "Add a second note"  # -a: сразу добавить все изменённые файлы
git log --oneline                 # 2 коммита, новые сверху
```

Ветка может называться `master` или `main` — это зависит от настроек git,
для лабораторных разницы нет. Если `git commit` открыл непонятный редактор, вы забыли `-m "..."`.
Выйти из редактора vim: Esc, затем `:q!` и Enter.

## Типичные ошибки

| что видите                                           | почему                                                  | что делать                                             |
| ---------------------------------------------------- | ------------------------------------------------------- | ------------------------------------------------------ |
| `Error: Cannot find module '.../hello.js'`           | терминал в другой папке, или опечатка в имени файла     | `pwd` и `ls`: где вы и есть ли файл                    |
| `node: command not found` / «не является командой»   | Node.js не установлен или терминал открыт до установки  | перезапустите терминал; проверьте `node --version`     |
| программа «висит», приглашение не появляется         | программа ждёт ввода или работает бесконечно            | Ctrl+C                                                 |
| `ReferenceError: document is not defined`            | `document`, `window`, `alert` есть только в браузере    | в Node.js печатайте через `console.log`                |
| `fatal: not a git repository`                        | команда git вне репозитория                             | перейдите в папку проекта или сделайте `git init`      |
| `Author identity unknown` при коммите                | git не знает ваше имя и почту                           | `git config --global user.name ...` и `user.email ...` |
| отладчик не останавливается на точке                 | программа запущена в обычном терминале, не в отладочном | JavaScript Debug Terminal                              |
| в PowerShell `touch` не найдена                      | такой команды в PowerShell нет                          | `New-Item имя-файла`                                   |
| `warning: ... LF will be replaced by CRLF` в Windows | git сообщает, что поменяет переводы строк под Windows   | это не ошибка; в лабораторной 1 это настраивается      |
