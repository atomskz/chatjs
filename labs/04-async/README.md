# Лабораторная 4. Асинхронность: Promise и async/await

**Цель:** понять, как Node.js выполняет асинхронный код в одном потоке;
научиться создавать промисы, ждать их через `await`, запускать операции
параллельно, ограничивать время ожидания и не терять ошибки.

**Понадобится:** лабораторные 1 и 3. Упражнения делайте в папке `sandbox-04`
с `"type": "module"` в `package.json` и не удаляйте её: в лабораторной 7 вы
напишете тесты для `async-utils.js`.

**Примерное время:** 2–2,5 часа.

## Теория

### Один поток и цикл событий

JavaScript в Node.js выполняется в одном потоке. Долгие операции
(сеть, диск, таймеры) не блокируют его: Node.js передаёт их операционной
системе и продолжает работу. Когда операция закончилась, её обработчик
встаёт в очередь, и **цикл событий** (event loop) вызывает его, как только
поток освободится.

Порядок выполнения:

1. весь синхронный код до конца;
2. **микрозадачи**: продолжения промисов (`.then`, код после `await`)
   и `queueMicrotask`;
3. **макрозадачи**: таймеры, готовый ввод-вывод, `setImmediate`.
   После каждой макрозадачи снова выполняются все микрозадачи.

Пока выполняется синхронный код, ни один обработчик не сработает.
Цикл `while (true) {}` в сервере «заморозит» всех клиентов разом.

### Таймеры

```js
const timer = setTimeout(() => console.log('once'), 1000); // один раз через секунду
clearTimeout(timer); // отменить, пока не сработал

const ticker = setInterval(() => console.log('tick'), 500); // каждые полсекунды
clearInterval(ticker); // остановить

setImmediate(() => console.log('soon')); // в ближайшем витке цикла событий
```

Время в таймерах — минимальное, а не точное: обработчик вызовется
не раньше указанного времени и только тогда, когда поток освободится.

### Callback

Исторически асинхронность в Node.js строилась на функциях обратного
вызова. Первым аргументом всегда приходит ошибка:

```js
readFile(path, 'utf8', (error, text) => {
  if (error) return console.error(error.message);
  console.log(text);
});
```

Несколько таких операций подряд дают «лесенку» вложенных функций.
Ошибку приходится проверять в каждом колбэке, и `try/catch` её не поймает.

### Promise

Промис — объект-обещание результата, который будет позже. У него
три состояния: `pending` (ждём), `fulfilled` (есть значение)
и `rejected` (есть ошибка). Из `pending` промис переходит в другое
состояние **один раз**: повторные `resolve`/`reject` игнорируются.

```js
function delay(ms, value) {
  return new Promise((resolve) => setTimeout(() => resolve(value), ms));
}

delay(500, 'hi')
  .then((value) => console.log(value))
  .catch((error) => console.error(error))
  .finally(() => console.log('done'));
```

### async / await

`async`-функция всегда возвращает промис. `await` приостанавливает её
до готовности промиса, не блокируя поток: в это время выполняется
другой код.

```js
async function main() {
  try {
    const text = await readFile(path, 'utf8'); // из node:fs/promises
    console.log(text);
  } catch (error) {
    console.error(error.message); // отклонённый промис превращается в исключение
  }
}
```

В ES-модулях `await` можно писать и на верхнем уровне файла.

### Готовые промисы вместо колбэков

Для большинства встроенных модулей есть версия с промисами:

```js
import { readFile } from 'node:fs/promises'; // readFile возвращает промис
const text = await readFile('notes.txt', 'utf8');

import { setTimeout as sleep } from 'node:timers/promises';
await sleep(500); // готовый delay

import { promisify } from 'node:util';
const readFileAsync = promisify(fs.readFile); // любая функция с колбэком (error, result)
```

### Как измерить время

```js
const start = Date.now();
await doSomething();
console.log(`took ${Date.now() - start} ms`);
```

### Несколько промисов

| функция              | ждёт                 | результат                                           |
| -------------------- | -------------------- | --------------------------------------------------- |
| `Promise.all`        | все                  | массив значений; первая же ошибка — отказ           |
| `Promise.allSettled` | все                  | массив `{status, value}` / `{status, reason}`       |
| `Promise.race`       | первый завершившийся | его значение или его ошибка                         |
| `Promise.any`        | первый успешный      | его значение; если все с ошибкой — `AggregateError` |

`await a(); await b();` выполняет операции **по очереди**.
`await Promise.all([a(), b()])` — **одновременно**.

### Что держит процесс живым

Node.js завершается сам, когда ему больше нечего ждать: нет активных
таймеров, сокетов, серверов. Забытый `setTimeout` на 5 секунд продержит
процесс 5 секунд. Есть два способа этого избежать:

- `clearTimeout(timer)` — отменить таймер, если он больше не нужен;
- `timer.unref()` — «не жди меня»: таймер сработает, только если процесс
  к тому времени ещё жив по другим причинам.

### Необработанный отказ

Если промис отклонён и у него нет `.catch` или `await` внутри `try`,
Node.js печатает ошибку и завершает процесс с кодом 1. Типичная причина —
забытый `await`.

Сохраните этот код в `order.js` и, **не запуская его**, запишите, в каком

### Упражнение 3. Последовательно или параллельно

Напишите async-функцию `fakeFetch(name, ms, shouldFail)`. Она ждёт `ms`
миллисекунд (через `await delay(ms)`) и возвращает `'<name> data'`, а если
`shouldFail` истинно — выбрасывает `Error('<name> failed')`. Измерьте через
`Date.now()` время:

- двух вызовов по 300 мс через `await` подряд (около 600 мс);
- тех же вызовов через `Promise.all` (около 300 мс);
- `Promise.all`, где второй вызов падает. Что вы получили?
- то же через `Promise.allSettled`.

### Упражнение 4. Ограничение времени

Добавьте в `async-utils.js` функцию `withTimeout(promise, ms)`.
Если промис не завершился за `ms` миллисекунд, она отклоняется с ошибкой,
у которой `code === 'ETIMEDOUT'`. Используйте `Promise.race`.

Внутри создайте промис с таймером, который вызывает `reject`, и устройте
`Promise.race` между ним и исходным промисом. В `.finally` вызовите
`clearTimeout`, чтобы таймер не держал процесс, когда исходный промис
уже выполнился.

Затем напишите `timeout.js`, который:

1. запоминает `const start = Date.now()` и подписывается на завершение процесса:
   `process.on('exit', () => console.log(...))` печатает, сколько прошло
   миллисекунд. Событие `exit` процесс испускает перед завершением
   (о событиях — в лабораторной 5);
2. ждёт быстрый промис с большим запасом: `await withTimeout(delay(100, 'done'), 5000)` —
   и печатает результат;
3. ждёт медленный промис с маленьким лимитом: `await withTimeout(delay(1000), 200)`
   внутри `try/catch` — и печатает `error.code`.

Сделайте второй вариант `withTimeout`, без `clearTimeout`, и запустите
`timeout.js` с каждым из вариантов:

```bash
node timeout.js        # process exited after ~1100 ms
node timeout.js leaky  # process exited after ~5000 ms
```

Откуда во втором случае лишние 4 секунды? А откуда в первом
1100 мс, а не 200? (Подсказка: `withTimeout` перестаёт ждать,
но `delay(1000)` внутри никто не отменял.)
