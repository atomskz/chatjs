## Занятие 1. Время, очередь и колбэки

### 1.1. Зачем это всё

Представьте кафе, в котором один официант. Он мог бы принять заказ, уйти
на кухню и стоять там, пока готовится блюдо. Остальные гости ждали бы.
Вместо этого он передаёт заказ повару, идёт к следующему столику, а когда
повар звонит в колокольчик — относит готовое блюдо.

Node.js работает как этот официант. Ваш код выполняется в **одном потоке**:
в каждый момент времени выполняется ровно одна строка. Долгие дела — ждать
таймер, читать файл, получать данные из сети — Node.js передаёт «на кухню»
(операционной системе) и сразу идёт дальше. Когда дело сделано, обработчик
результата встаёт в **очередь**, и Node.js выполнит его, когда освободится.

Код, который не ждёт результата на месте, а получает его позже, называется
**асинхронным**.

### 1.2. Первый асинхронный вызов: `setTimeout`

`setTimeout(функция, мс)` просит: «выполни эту функцию не раньше чем через
столько миллисекунд». Сам вызов **не ждёт**: он ставит функцию в очередь
и сразу возвращается.

**Разобранный пример.** Сохраните и запустите:

```js
console.log('1');
setTimeout(() => console.log('2'), 0);
console.log('3');
```

Вывод:

```
1
3
2
```

Даже с задержкой 0 строка `2` печатается последней. Что происходило по шагам:

| шаг | что выполняется               | очередь таймеров   | вывод |
| --- | ----------------------------- | ------------------ | ----- |
| 1   | `console.log('1')`            | —                  | `1`   |
| 2   | `setTimeout(...)`             | `() => log('2')`   |       |
| 3   | `console.log('3')`            | `() => log('2')`   | `3`   |
| 4   | файл выполнен, поток свободен | берём из очереди → | `2`   |

Главное правило: **функция из очереди выполнится только после того,
как закончится весь текущий код.** Пока поток занят, очередь ждёт.

### 1.3. Пока поток занят, ничего не происходит

Если занять поток долгим вычислением, таймеры опоздают:

```js
const start = Date.now();
setTimeout(() => console.log(`timer fired after ${Date.now() - start} ms`), 100);
while (Date.now() - start < 1000) {
  // ничего не делаем — просто заняли поток на секунду
}
console.log('loop done');
```

```
loop done
timer fired after 1002 ms
```

Таймер просили на 100 мс, а сработал он через секунду: всё это время
поток был занят циклом. Так же в сервере чата один «тяжёлый» обработчик
заморозил бы всех клиентов сразу. Поэтому в Node.js ничего не ждут
«в лоб», а долгие операции делают асинхронными.

`Date.now()` возвращает текущее время в миллисекундах. Разница двух
вызовов — сколько прошло времени.

### 1.4. Таймеры: шпаргалка

```js
const timer = setTimeout(() => console.log('once'), 1000); // один раз через секунду
clearTimeout(timer); // отменить, пока не сработал

const ticker = setInterval(() => console.log('tick'), 500); // каждые полсекунды
clearInterval(ticker); // остановить

setImmediate(() => console.log('soon')); // в ближайшем витке цикла событий
```

`setTimeout` и `setInterval` возвращают объект таймера. Сохраните его
в переменную, если таймер может понадобиться отменить. Время в таймерах —
минимальное, а не точное: обработчик вызовется не раньше указанного срока
и только когда поток освободится.

### 1.5. Цикл событий

То, что выбирает следующую задачу из очереди, называется **циклом событий**
(event loop). Очередей на самом деле две, и у них разный приоритет:

```
        ┌────────────────────────────────┐
        │ 1. весь синхронный код файла    │
        └───────────────┬────────────────┘
                        ▼
        ┌────────────────────────────────┐
   ┌───►│ 2. ВСЕ микрозадачи              │◄── .then промисов, код после await,
   │    └───────────────┬────────────────┘    queueMicrotask
   │                    ▼
   │    ┌────────────────────────────────┐
   │    │ 3. одна макрозадача             │◄── таймеры, готовые файлы и сеть,
   │    └───────────────┬────────────────┘    setImmediate
   └────────────────────┘
        если ждать больше нечего — процесс завершается
```

- **Микрозадачи** — продолжения промисов (о них — во втором занятии).
  Выполняются сразу, как только освободился поток, и все до одной.
- **Макрозадачи** — таймеры, ответы от файлов и сети, `setImmediate`.
  После каждой из них снова выполняются все накопившиеся микрозадачи.
- Внутри одной очереди порядок «первым пришёл — первым вышел».

Пока этого достаточно запомнить так: **сначала синхронный код, потом
промисы, потом таймеры и ввод-вывод.**

### 1.6. Колбэки

**Колбэк** (callback, «обратный вызов») — функция, которую вы передаёте
другой функции, чтобы та вызвала её, когда будет результат. Вы уже
передавали колбэк в `setTimeout`. Так же устроены многие функции Node.js,
например чтение файла:

```js
import { readFile } from 'node:fs'; // версия с колбэком

console.log('before');
readFile(import.meta.filename, 'utf8', (error, text) => {
  console.log('file read');
});
console.log('after');
```

```
before
after
file read
```

`import.meta.filename` — путь к текущему файлу: программа читает сама себя.
Колбэк вызывается позже, когда файл прочитан, — после `after`.

**Соглашение Node.js: первым аргументом колбэка всегда идёт ошибка.**
Если всё хорошо, она равна `null`, а результат — во втором аргументе:

```js
readFile('notes.txt', 'utf8', (error, text) => {
  if (error) {
    console.error(`Cannot read: ${error.code}`); // например ENOENT — нет файла
    return;
  }
  console.log(text);
});
```

**Почему `try/catch` здесь не помогает.** Когда ошибка чтения станет
известна, функция, где был `try`, уже давно закончилась. Поэтому ошибку
проверяют внутри колбэка, через `if (error)`.

**Почему из колбэка нельзя «вернуть» результат.** Частая ошибка новичков:

```js
function readName(callback) {
  setTimeout(() => callback('Ann'), 10);
}
function getName() {
  readName((name) => {
    return name; // вернёт из стрелочной функции, а не из getName
  });
}
console.log(getName()); // undefined
```

`getName` закончилась сразу, ничего не вернув, а `return name` выполнился
через 10 мс внутри другой функции. Результат асинхронной операции можно
использовать только **внутри колбэка** (или через промис — во втором занятии).

**«Лесенка».** Если операции нужно делать по очереди, колбэки вкладываются
друг в друга, и код уезжает вправо:

```js
readFile('a.txt', 'utf8', (errorA, a) => {
  if (errorA) return console.error(errorA.message);
  readFile('b.txt', 'utf8', (errorB, b) => {
    if (errorB) return console.error(errorB.message);
    console.log(a + b);
  });
});
```

Такой код трудно читать и легко забыть проверить ошибку. Промисы решают
именно эту проблему.

## Занятие 2. Promise и async/await

### 2.1. Промис — квитанция на будущий результат

В кафе вам дают квитанцию: «заказ принят». Блюда ещё нет, но квитанция
уже есть, и по ней вы его потом получите. **Промис** (Promise, «обещание») —
такая квитанция: объект, который появляется сразу, а результат в нём
появится позже.

У промиса три состояния:

```
                    resolve(value)
       ┌──────────► fulfilled (выполнен) ──► .then((value) => ...)
pending │
(ждём)  │
       └──────────► rejected (отклонён) ───► .catch((error) => ...)
                    reject(error) или throw
```

Промис меняет состояние **один раз**: после `resolve` или `reject` повторные
вызовы ничего не делают.

### 2.2. Разобранный пример: делаем свой промис

Напишем `delay(ms, value)` — промис, который выполнится через `ms`
миллисекунд со значением `value`.

**Шаг 1.** `new Promise(функция)` создаёт промис. Функцию внутри называют
исполнителем (executor). Node.js вызывает её **сразу** и передаёт ей
два «рычага»: `resolve` — выполнить промис, `reject` — отклонить.

```js
const p = new Promise((resolve) => {
  console.log('executor');
  resolve('value');
});
console.log('after new Promise');
p.then((v) => console.log(v));
console.log('end');
```

```
executor
after new Promise
end
value
```

Исполнитель выполнился сразу (`executor` — первая строка). А `.then`
вызвал свою функцию позже — микрозадачей, когда закончился синхронный код.

**Шаг 2.** Чтобы промис выполнился через время, вызовем `resolve`
из таймера:

```js
function delay(ms, value) {
  return new Promise((resolve) => {
    setTimeout(() => resolve(value), ms);
  });
}

delay(500, 'hi').then((value) => console.log(value)); // через полсекунды: hi
```

**Шаг 3.** Методы промиса:

```js
delay(500, 'hi')
  .then((value) => console.log(value)) // если выполнен
  .catch((error) => console.error(error.message)) // если отклонён
  .finally(() => console.log('done')); // в любом случае
```

**Цепочка.** `.then` возвращает **новый** промис со значением, которое
вернула функция внутри. Поэтому `.then` можно ставить друг за другом:

```js
Promise.resolve(1)
  .then((x) => x + 1) // 2
  .then((x) => {
    console.log(x); // 2
    return x * 10;
  })
  .then((x) => console.log(x)); // 20
```

`Promise.resolve(value)` — готовый выполненный промис, `Promise.reject(error)` —
готовый отклонённый. Удобно в примерах и тестах.

### 2.3. Из колбэка в промис

Так же, как `delay`, можно «обернуть» любую функцию с колбэком:

```js
import { readFile } from 'node:fs';

function readText(path) {
  return new Promise((resolve, reject) => {
    readFile(path, 'utf8', (error, text) => {
      if (error) {
        reject(error); // ошибка колбэка → промис отклонён
      } else {
        resolve(text); // результат колбэка → промис выполнен
      }
    });
  });
}

readText('notes.txt')
  .then((text) => console.log(text))
  .catch((error) => console.error(error.code));
```

Делать это руками приходится редко: для встроенных модулей есть готовые
версии с промисами.

```js
import { readFile } from 'node:fs/promises'; // этот readFile сразу возвращает промис
import { setTimeout as sleep } from 'node:timers/promises'; // готовый delay

import { readFile as readFileCallback } from 'node:fs';
import { promisify } from 'node:util';
const readFileAsync = promisify(readFileCallback); // любая функция с колбэком (error, result)
```

`import { readFile as readFileCallback }` — импорт с переименованием:
в `node:fs` и в `node:fs/promises` функции называются одинаково, и чтобы
использовать обе в одном файле, одной дают другое имя.

### 2.4. `async` и `await`

Цепочки `.then` тоже бывают длинными. `async/await` позволяет писать
асинхронный код так, будто он синхронный.

- `async` перед функцией значит: она **всегда возвращает промис**.
- `await промис` внутри неё значит: «подожди результат и дай мне значение».
  Поток при этом не блокируется: пока функция ждёт, выполняется другой код.

**Разобранный пример.** Та же логика тремя способами:

```js
// 1. Колбэки
readFile('a.txt', 'utf8', (error, a) => {
  if (error) return console.error(error.message);
  console.log(a);
});

// 2. Промис и .then
readText('a.txt')
  .then((a) => console.log(a))
  .catch((error) => console.error(error.message));

// 3. async/await
async function main() {
  try {
    const a = await readText('a.txt'); // ждём значение, а не квитанцию
    console.log(a);
  } catch (error) {
    console.error(error.message); // отклонённый промис превращается в исключение
  }
}
main();
```

Третий вариант читается сверху вниз, а ошибки снова ловит обычный `try/catch`.
«Лесенка» из 1.6 превращается в две строки подряд:

```js
const a = await readText('a.txt');
const b = await readText('b.txt');
console.log(a + b);
```

В ES-модулях `await` можно писать и прямо в файле, вне функции.

**Что вернёт async-функция.** Всегда промис — даже если внутри обычный `return`:

```js
async function getNumber() {
  return 42;
}
console.log(getNumber()); // Promise { 42 } — квитанция, а не число
console.log(await getNumber()); // 42
```

**Исключение внутри async-функции** не вылетает в момент вызова,
а превращает промис в отклонённый:

```js
async function load() {
  throw new Error('broken'); // то же, что вернуть Promise.reject(new Error('broken'))
}

try {
  load(); // без await: исключения здесь нет, есть только отклонённый промис
} catch {
  console.log('never printed');
}

try {
  await load(); // с await отклонение снова становится исключением
} catch (error) {
  console.log(`caught: ${error.message}`); // caught: broken
}
```

Иногда async-функцию нужно сразу вызвать, не давая ей имени:
`(async () => { ... })();`. Внешние скобки делают из функции выражение,
а `()` в конце её вызывают.

### 2.5. Несколько промисов: по очереди или вместе

```js
await delay(200);
await delay(200); // начнётся только после первого — всего ≈ 400 мс

await Promise.all([delay(200), delay(200)]); // оба сразу — всего ≈ 200 мс
```

```
по очереди:   a ████████
                        b ████████        ≈ 400 мс

вместе:       a ████████
              b ████████                  ≈ 200 мс
```

`Promise.all([...])` запускает ожидание всех промисов сразу и возвращает
массив их значений в том же порядке.

| функция              | ждёт                 | результат                                           |
| -------------------- | -------------------- | --------------------------------------------------- |
| `Promise.all`        | все                  | массив значений; первая же ошибка — отказ           |
| `Promise.allSettled` | все                  | массив `{ status, value }` / `{ status, reason }`   |
| `Promise.race`       | первый завершившийся | его значение или его ошибка                         |
| `Promise.any`        | первый успешный      | его значение; если все с ошибкой — `AggregateError` |

- У `Promise.allSettled` поле `status` — `'fulfilled'` (тогда есть `value`)
  или `'rejected'` (тогда есть `reason` — ошибка).
- `Promise.all` при первой ошибке сразу отклоняется, но **не отменяет**
  остальные операции: они продолжают работать, просто их результат никто не ждёт.

**Ловушка с `forEach`.** `forEach` не умеет ждать промисы:

```js
names.forEach(async (name) => {
  await delay(10);
  console.log(name);
});
console.log('done'); // напечатается ПЕРВЫМ
```

По очереди — `for (const name of names) { await ... }`, все сразу —
`await Promise.all(names.map(async (name) => { ... }))`.

### 2.6. Что держит процесс живым

Node.js завершается сам, когда ждать больше нечего: нет таймеров, открытых
файлов, сокетов, серверов. Забытый `setTimeout` на 5 секунд продержит
процесс 5 секунд, а забытый `setInterval` — вечно.

- `clearTimeout(timer)` / `clearInterval(timer)` — отменить таймер;
- `timer.unref()` — «не жди меня»: таймер сработает, только если процесс
  к этому времени ещё жив по другим причинам.

Промис, который никто никогда не выполнит, процесс **не** держит. Если
ждать его через `await` на верхнем уровне файла, Node.js завершится
с предупреждением «Detected unsettled top-level await» и кодом выхода 13.
Обычно это значит, что вы забыли вызвать `resolve`.

### 2.7. Необработанный отказ

Если промис отклонён и у него нет ни `.catch`, ни `await` внутри `try`,
Node.js печатает ошибку и **завершает процесс** с кодом 1. Происходит это
быстро: как только закончились микрозадачи и стало ясно, что отказ
никто не обработал, — ещё до того, как сработают таймеры.

Исправить можно `await` внутри `try/catch` или методом `.catch`:

```js
loadConfig().catch((error) => {
  console.error(`Cannot start: ${error.message}`);
  process.exitCode = 1;
});
```

### 2.8. Сравнение с «один поток на клиента»

Во многих серверах на других языках каждому клиенту выделяют свой поток,
который просто ждёт данных от своего сокета.

|                   | один поток на клиента                            | цикл событий (Node.js)                          |
| ----------------- | ------------------------------------------------ | ----------------------------------------------- |
| как писать код    | просто: «прочитай, ответь» сверху вниз           | колбэки, промисы, `await`                       |
| память            | у каждого потока свой стек (порядка 1 МБ)        | на клиента — только его объекты                 |
| тысячи клиентов   | тысячи потоков, ОС тратит время на переключение  | один поток спит, пока никто не пишет            |
| общие данные      | нужны блокировки: два потока меняют одно и то же | блокировки не нужны: код выполняется по очереди |
| долгое вычисление | тормозит только своего клиента                   | замораживает **всех** клиентов (пример 1.3)     |

### Упражнение 1. Угадайте порядок

Сохраните этот код в `order.js` и, **не запуская его**, запишите, в каком
порядке появятся буквы. Опирайтесь на схему цикла событий из 1.5:

```js
console.log('A');
setTimeout(() => console.log('B'), 0);
setImmediate(() => console.log('C'));
Promise.resolve().then(() => console.log('D'));
queueMicrotask(() => console.log('E'));
(async () => {
  console.log('F');
  await null;
  console.log('G');
})();
console.log('H');
```

Подсказки: `queueMicrotask(fn)` просто ставит `fn` в очередь микрозадач.
Код после `await` тоже становится микрозадачей — в тот момент, когда
выполнение дошло до `await`.

Запустите несколько раз. Почему `B` и `C` иногда меняются местами?
(Порядок `setTimeout(0)` и `setImmediate` в главном файле зависит от того,

### Упражнение 6. Ограничение времени

Добавьте в `async-utils.js` функцию `withTimeout(promise, ms)`.
Если промис не завершился за `ms` миллисекунд, она отклоняется с ошибкой,
у которой `code === 'ETIMEDOUT'`.

Внутри создайте промис с таймером, который вызывает `reject`, и устройте
`Promise.race` между ним и исходным промисом. В `.finally` вызовите
`clearTimeout`, чтобы таймер не держал процесс, когда исходный промис
уже выполнился. Ошибку с кодом можно создать так:
`Object.assign(new Error('Timed out'), { code: 'ETIMEDOUT' })`.

Затем напишите `timeout.js`, который:

1. запоминает `const start = Date.now()` и подписывается на завершение процесса:
   `process.on('exit', () => console.log(...))` печатает, сколько прошло
   миллисекунд. Событие `exit` процесс испускает перед завершением
   (о событиях — в лабораторной 5);
2. ждёт быстрый промис с большим запасом: `await withTimeout(delay(100, 'done'), 5000)` —
   и печатает результат;
3. ждёт медленный промис с маленьким лимитом: `await withTimeout(delay(1000), 200)`
   внутри `try/catch` — и печатает `error.code`.

Сделайте второй вариант `withTimeout`, без `clearTimeout`, и запустите
`timeout.js` с каждым из вариантов:

```bash
node timeout.js        # process exited after ~1100 ms
node timeout.js leaky  # process exited after ~5000 ms
```

Откуда во втором случае лишние 4 секунды? А откуда в первом
1100 мс, а не 200? (Подсказка: `withTimeout` перестаёт ждать,
но `delay(1000)` внутри никто не отменял.)

## Типичные ошибки

| что видите                                      | почему                                                    | что делать                                              |
| ----------------------------------------------- | --------------------------------------------------------- | ------------------------------------------------------- |
| `Promise { <pending> }` вместо значения         | забыт `await`: напечатана квитанция, а не результат       | `await` перед вызовом                                   |
| `undefined` из функции, внутри которой колбэк   | `return` в колбэке возвращает из колбэка, а не из функции | вернуть промис и `await`-ить его (2.3)                  |
| в цепочке `.then` пришло `undefined`            | в фигурных скобках `.then` забыт `return`                 | `return` значение или стрелка без `{}`                  |
| `try/catch` не поймал ошибку async-функции      | вызов без `await`: в `try` попал только промис            | `await` внутри `try`                                    |
| «finished» печатается раньше работы             | `forEach` с async-колбэком не ждёт                        | `for...of` с `await` или `Promise.all(map(...))`        |
| всё работает, но медленно                       | `await` по очереди там, где можно одновременно            | `Promise.all`                                           |
| программа не завершается после работы           | остался таймер или интервал                               | `clearTimeout` / `clearInterval` или `unref()`          |
| `Detected unsettled top-level await`, код 13    | ждём промис, который никто не выполнит                    | проверить, что `resolve` или `reject` вызывается всегда |
| процесс упал, в выводе ошибка из промиса, код 1 | необработанный отказ                                      | `try/catch` вокруг `await` или `.catch(...)`            |
