# Лабораторная 4. Ответы

Сначала ответьте сами и запустите код, потом сверяйтесь.

## Разминки

### Разминка 1

1. `C`, `B`, `A`. Синхронный `console.log('C')` выполняется сразу. Таймеры
   ждут, пока закончится файл, и срабатывают по времени: через 50 мс `B`,
   через 100 мс `A`. Порядок вызовов `setTimeout` в коде не важен, важен срок.
2. Около 100 мс. Цикл займёт поток только на 50 мс, а таймер по-прежнему
   ждёт свои 100: к этому моменту поток уже свободен, и таймер срабатывает
   вовремя. Время в таймере — **минимальное**: раньше он не сработает,
   а позже — только если поток занят.

### Разминка 2

1. `before`, `after`, затем — ваш вывод из ветки ошибки (например,
   `Cannot read: ENOENT`). Порядок тот же: колбэк вызывается после
   синхронного кода, неважно, успешно чтение или нет.
2. `getName` вызвала `readName` и сразу закончилась, ничего не вернув,
   поэтому `undefined`. `return name` выполнился через 10 мс, внутри
   стрелочной функции-колбэка, и вернул значение из **неё** — тому, кто
   её вызвал (таймеру). Из `getName` он уже ничего вернуть не может.

### Разминка 3

1. `undefined`. В стрелочной функции с фигурными скобками нужен явный
   `return`. Выражение `x + 1` вычислилось и пропало, функция вернула
   `undefined`, и следующий `.then` получил его. Варианты исправления:
   `.then((x) => x + 1)` или `{ return x + 1; }`.
2. ```js
   function delayReject(ms) {
     return new Promise((_, reject) => {
       setTimeout(() => reject(new Error('too late')), ms);
     });
   }

   delayReject(100).catch((error) => console.log(error.message)); // too late
   ```

### Разминка 4

1. `Promise { 42 }` — сам промис. Число получают через
   `await getNumber()` или `getNumber().then((n) => console.log(n))`.
2. Исключение никто не поймает: Node.js напечатает `Error: broken` со стеком
   и завершит процесс с кодом 1. Код после этого `await` не выполнится.

## Контрольные вопросы

1. Поток не ждёт долгие операции на месте: он передаёт их операционной
   системе и выполняет следующий код. Когда операция закончилась,
   её обработчик встаёт в очередь, и цикл событий вызывает его, как только
   поток свободен. Так один поток успевает обслуживать много операций
   по очереди короткими кусочками.
2. `setTimeout` только ставит функцию в очередь. Функции из очереди
   выполняются, когда закончится весь текущий синхронный код, даже если
   задержка 0.
3. `.then`. Его функция — микрозадача, а `setTimeout` — макрозадача.
   Все микрозадачи выполняются раньше следующей макрозадачи.
4. Когда ошибка станет известна, функция с `try` уже закончилась: вокруг
   колбэка в момент его вызова нет вашего `try`. Поэтому ошибку проверяют
   в самом колбэке (`if (error)`), а с промисами — через `await` внутри
   `try` или `.catch`.
5. Ничего: промис меняет состояние один раз. Второй `resolve` (как и `reject`
   после `resolve`) игнорируется без ошибки.
6. Всегда промис. `return value` делает его выполненным со значением `value`,
   а `throw error` — отклонённым с этой ошибкой. В момент вызова исключение
   наружу не вылетает.
7. Первый вариант ждёт `a`, и только потом **начинает** `b`: время
   складывается. Второй запускает оба сразу и ждёт оба: время — как у самого
   долгого.
8. Когда нужны результаты всех операций, даже если часть упала. `Promise.all`
   при первой же ошибке отклоняется, и результаты успешных теряются.
9. Активный таймер — это дело, которого процесс ещё ждёт: Node.js не
   завершается, пока такие дела есть. `unref()` говорит «этот таймер
   не повод ждать»: если больше ничего нет, процесс завершится, не дожидаясь
   таймера.
10. Отклонённый промис, у которого нет ни `.catch`, ни `await` внутри `try`.
    Node.js завершает процесс с кодом 1. Избежать: всегда ждать промисы
    через `await` в `try/catch` или вешать `.catch`, особенно на вызовы
    async-функций без `await`.
