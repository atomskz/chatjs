# Лабораторная 9. Терминал: `readline`, ввод и вывод

**Цель:** научиться читать ввод пользователя построчно, выводить сообщения
так, чтобы они не ломали набираемый текст, обрабатывать Ctrl+C и Ctrl+D
и отделять интерфейс от логики программы.

**Понадобится:** лабораторные 4 и 5. Упражнения делайте в папке
`sandbox-09` с `"type": "module"`.

**Где запускать в Windows.** Интерактивные упражнения (ввод с клавиатуры,
Ctrl+C, вывод над строкой ввода) запускайте в Windows Terminal, PowerShell
или cmd. В Git Bash программа иногда не видит терминал: проверьте
`node -e "console.log(process.stdout.isTTY)"`. Если напечаталось `undefined`,
запускайте через `winpty node app.js`. Упражнения с конвейером (`printf ... |`),
наоборот, удобнее делать в Git Bash (см. 1.2).

**Примерное время:** 4 часа, два занятия.

**Как работать:** каждый пример запускайте у себя и сверяйте вывод.
В разминках сначала запишите **свой** ответ, потом проверьте и только
потом смотрите [answers.md](answers.md).

## Занятие 1. Чтение ввода

### 1.1. Зачем

Клиент чата делает две вещи одновременно: пользователь набирает сообщение,
а в это время приходят сообщения от других. Нужно читать ввод **построчно**
(отправлять, когда нажали Enter) и печатать входящие так, чтобы они
не перемешались с тем, что человек сейчас набирает.

**Аналогия: секретарь.** Вы диктуете, секретарь записывает и отдаёт вам
лист, только когда вы сказали «точка» (нажали Enter). В Node.js такой
секретарь — модуль `readline`: он собирает нажатия клавиш в строку и сообщает
событием, когда строка готова.

### 1.2. Потоки ввода и вывода

У процесса три стандартных потока:

```
клавиатура ─┐                        ┌─► экран
файл (<)   ─┼─► stdin ─► программа ─┼─► stdout ─► > файл / | другая программа
конвейер (|)┘                        └─► stderr ─► экран
```

```bash
node app.js                      # ввод с клавиатуры
node app.js < input.txt          # ввод из файла
printf 'a\nb\n' | node app.js    # ввод из конвейера
```

В PowerShell то же самое пишется так:

```powershell
Get-Content input.txt | node app.js   # оператора < в PowerShell нет
"a", "b" | node app.js                # каждая строка массива — строка ввода
```

Windows PowerShell 5.1 при передаче текста в программу может испортить
кириллицу (`?` вместо букв) или добавить в начало невидимый символ BOM.
Тогда первая строка придёт как `\uFEFFhello`, и сравнение `line === 'exit'`
или `JSON.parse` сломаются. Упражнения с конвейером делайте в Git Bash
или PowerShell 7 (`pwsh`).

**Терминал или нет.** `process.stdout.isTTY` равно `true`, только если вывод
идёт в настоящее окно терминала. В файл или в конвейер — `undefined`:

```bash
node -e "console.log(process.stdout.isTTY)"          # true
node -e "console.log(process.stdout.isTTY)" | cat    # undefined
```

Когда вывод не в терминал, управлять курсором и цветами бессмысленно,
и программа должна это проверять.

### 1.3. Разобранный пример: эхо

```js
import readline from 'node:readline';

const rl = readline.createInterface({ input: process.stdin, output: process.stdout });
let count = 0;
let isClosed = false;

rl.setPrompt('echo> ');
rl.prompt(); // нарисовать приглашение

rl.on('line', (line) => {
  if (isClosed) return; // см. ловушку 1 в 1.6
  if (line.trim() === 'exit') {
    rl.close();
    return;
  }
  count++;
  console.log(line.toUpperCase());
  rl.prompt(); // после Enter приглашение нужно нарисовать снова
});

rl.on('close', () => {
  isClosed = true;
  console.log(`\nLines: ${count}. Bye!`);
});
```

```
$ printf 'hello\nпривет 😀\nexit\nignored\n' | node echo-repl.js
echo> HELLO
echo> ПРИВЕТ 😀
echo>
Lines: 2. Bye!
```

Что здесь происходит:

- `readline.createInterface({ input, output })` — «секретарь» читает из
  `input` и пишет приглашение в `output`;
- `rl.prompt()` только **рисует** приглашение. После Enter `readline` сам его
  не перерисовывает: без `rl.prompt()` в обработчике `line` вы увидите
  `> got a`, а следующие строки — уже без `> `;
- событие `line` приходит с готовой строкой без символа перевода строки;
- событие `close` приходит, когда ввод закончился: `rl.close()`, Ctrl+D
  или конец файла или конвейера;
- приглашение печатается в `output`, даже если ввод идёт из конвейера.
  Поэтому в выводе выше есть `echo> `.

Приглашение можно задать сразу: `createInterface({ input, output, prompt: '> ' })`.

### 1.4. Ctrl+C и Ctrl+D

| что нажали | интерактивный терминал                                                                | ввод из файла или конвейера               |
| ---------- | ------------------------------------------------------------------------------------- | ----------------------------------------- |
| Ctrl+D     | на пустой строке — «ввод закончился», придёт `close`                                  | конец ввода и так придёт сам              |
| Ctrl+C     | `readline` испускает `SIGINT` на `rl`; без обработчика — просто закрывается (`close`) | сигнал получает процесс (лабораторная 14) |

```js
rl.on('SIGINT', () => {
  /* Ctrl+C: спросить подтверждение, выйти и т. д. */
});
```

Если обработчика `SIGINT` нет, `readline` просто закрывается. Процесс
завершится, только если его больше ничего не держит: работающий таймер или
открытое соединение оставят его жить (лабораторные 4 и 14).

### 1.5. Вопрос и ответ: `question`

`question` печатает вопрос и ждёт **одну следующую** строку. Есть две формы:

```js
// С колбэком — модуль node:readline
rl.question('Really quit? (y/n) ', (answer) => {
  if (answer === 'y') rl.close();
});
```

```js
// С промисом — модуль node:readline/promises
import readline from 'node:readline/promises';

const rl = readline.createInterface({ input: process.stdin, output: process.stdout });
const name = await rl.question('What is your name? ');
```

**Строки как асинхронный итератор** (лабораторная 5):

```js
for await (const line of rl) {
  console.log(`got ${line}`);
} // цикл закончится, когда ввод закончится

// или по одной строке:
const lines = rl[Symbol.asyncIterator]();
process.stdout.write('What is your name? '); // вопрос печатаем сами
const { value, done } = await lines.next(); // done === true — ввод закончился
```

`Symbol.asyncIterator` — стандартное «имя» метода, который возвращает
асинхронный итератор. Его вызывает `for await` сам, а вручную — когда нужно
читать строки по одной через `next()`.

### 1.6. Две ловушки

1. **Строки после `close()`.** Если несколько строк пришли одним куском
   (из файла или конвейера), `readline` делит кусок на строки и в цикле
   испускает `line` для каждой. `rl.close()` внутри обработчика этот цикл
   не останавливает, и строки после `exit` всё равно придут. А `rl.prompt()`
   после закрытия выбрасывает `Error [ERR_USE_AFTER_CLOSE]: readline was closed`.
   Решение — флаг «уже закрыто», как `isClosed` в примере 1.3.
2. **`rl.question` и конвейер.** `question` ждёт **следующую** строку.
   Строки, прочитанные до вызова `question`, теряются. С клавиатуры
   этого не видно, а с конвейером второй вопрос не получит ответа,
   и процесс завершится с кодом 13 («Detected unsettled top-level await»).
   Надёжнее асинхронный итератор: он складывает строки в очередь.

## Занятие 2. Вывод: курсор, цвета, интерфейс

### 2.1. `write` и `console.log`

`console.log` всегда пишет в `process.stdout` и сам добавляет перевод строки.
У любого потока вывода есть метод `write`: он пишет ровно то, что ему
передали, без перевода строки.

```js
process.stdout.write('no newline'); // курсор остаётся в конце этой строки
output.write(`${line}\n`); // сами добавляем перевод строки
```

Если класс получает поток вывода параметром (`output`), печатать нужно
через `output.write`, а не через `console.log`. Иначе подставить другой
поток, например для теста, не получится.

### 2.2. Управление курсором

Терминал — не просто лента текста: в нём есть курсор, который можно
двигать, и строки, которые можно стирать. Для этого в вывод вставляют
специальные **escape-последовательности**, а `readline` даёт для них функции:

```js
readline.cursorTo(process.stdout, 0); // курсор в колонку 0, в начало строки
readline.clearLine(process.stdout, 0); // 0 — стереть всю строку (-1 — слева от курсора, 1 — справа)
readline.moveCursor(process.stdout, 0, -1); // сдвиг: 0 колонок, на 1 строку вверх
```

**Разобранный пример: строка, которая перерисовывается на месте.**
[solution/progress.js](solution/progress.js) рисует полосу прогресса,
не добавляя новых строк:

```js
function render() {
  const bar = '#'.repeat(done) + '.'.repeat(total - done);
  const line = `[${bar}] ${done * 10}%`;
  if (output.isTTY) {
    readline.cursorTo(output, 0); // курсор в начало строки
    readline.clearLine(output, 0); // стереть старый вариант строки
    output.write(line); // нарисовать новый — без перевода строки
  } else {
    output.write(`${line}\n`); // без терминала курсором не управляют
  }
}
```

В терминале видна одна растущая строка `[###.......] 30%`. В файле
(`node progress.js > out.txt`) — по строке на каждый шаг: в файле курсора нет,
и escape-последовательности превратились бы в мусор.

### 2.3. Вывод над строкой ввода

Если просто вызвать `console.log`, пока пользователь набирает текст,
сообщение приклеится к набранному: `> привmessage from bob`. Правильно так:

```
было:     > прив█

шаг 1:    █                    курсор в начало строки, строка стёрта
шаг 2:    [12:00:01] tick      напечатали сообщение с переводом строки
          █
шаг 3:    [12:00:01] tick
          > прив█              rl.prompt(true) нарисовал приглашение и набранный текст
```

```js
function printAbovePrompt(text) {
  if (!output.isTTY) {
    output.write(`${text}\n`); // в файл или конвейер — просто строкой
    return;
  }
  readline.cursorTo(output, 0); // шаг 1
  readline.clearLine(output, 0);
  output.write(`${text}\n`); // шаг 2
  rl.prompt(true); // шаг 3: true — сохранить набранный текст и позицию курсора
}
```

Для простоты считается, что набранный текст помещается в одну строку
терминала.

### 2.4. Цвета

```js
import { styleText } from 'node:util';
console.log(styleText('red', '! error'));
console.log(styleText(['bold', 'green'], 'you'));
```

`styleText` сама проверяет поток вывода и не добавляет escape-коды,
если вывод идёт не в терминал (а также если задана переменная `NO_COLOR`).
По умолчанию проверяется `process.stdout`. Если вы пишете в другой поток,
передайте его: `styleText('red', text, { stream: output })`.

### 2.5. Интерфейс отдельно от логики

```
            события: 'line' (text), 'quit'
TerminalUI ────────────────────────────────► ChatClient
(readline,  ◄──────────────────────────────── (логика: что отправить,
 курсор,     методы: printChat, printSystem,    как реагировать на сервер)
 цвета)              printInfo, printError
```

Класс интерфейса умеет только показывать текст и сообщать о действиях
пользователя событиями. Что делать с введённой строкой, решает логика
клиента. Тогда логику можно протестировать с поддельным интерфейсом
(так и сделано в лабораторной 15), а интерфейс заменить, не трогая логику.

| что видите                                            | почему                                                       | что делать                                                   |
| ----------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `Error [ERR_USE_AFTER_CLOSE]: readline was closed`    | `rl.prompt()` после `close()`: строки из буфера пришли позже | флаг «закрыто», проверка в обработчике `line` (1.6)          |
| `Detected unsettled top-level await`, код 13          | `rl.question` с конвейером потерял строку                    | асинхронный итератор вместо `question`                       |
| входящее сообщение приклеилось: `> привmessage`       | `console.log` поверх строки ввода                            | вывод над строкой ввода (2.3)                                |
| после первой строки пропало приглашение `> `          | `rl.prompt()` не вызван в обработчике `line`                 | `rl.prompt()` после обработки каждой строки                  |
| набранный текст пропал после входящего сообщения      | `rl.prompt()` без `true` или не вызван                       | `rl.prompt(true)`                                            |
| программа не завершается после Ctrl+C или Ctrl+D      | работает таймер или открыто соединение                       | остановить таймер и закрыть соединение в обработчике `close` |
| в файле мусор вида `[31m` или `[2K`                   | курсор и цвета выводятся не в терминал                       | проверять `output.isTTY`; `styleText` вместо ручных кодов    |

| время `2:05:12 PM` вместо `14:05:12`                  | `toLocaleTimeString()` зависит от настроек системы           | `formatTime` из шага проекта                                 |

| `quit` пришёл, когда программа сама закрыла интерфейс | `close` у `readline` испускает `quit` без проверки           | флаг `#isClosed` в `TerminalUI` (шаг проекта)                |

## Шаг проекта

Создайте `lib/terminal-ui.js` с классом `TerminalUI extends EventEmitter`:

- `constructor({ input = process.stdin, output = process.stdout } = {})` —
  `= {}`, чтобы работал вызов `new TerminalUI()` без аргументов;
- события: `line` (text) — введена строка; `quit` — Ctrl+C, Ctrl+D или конец ввода;
- методы `printChat({ from, text, ts, isOwn })`, `printSystem(text, ts = Date.now())`
  (время по умолчанию — сейчас: так удобно для своих локальных уведомлений),
  `printInfo(text)`, `printError(text)` в формате из раздела 6.2 ТЗ:

  ```
  [14:05:12] alice: Привет всем!
  [14:05:20] * bob joined the chat
  ```

  Время берётся из `ts` (миллисекунды) и форматируется так:

  ```js
  function formatTime(ts) {
    const date = new Date(ts);
    return [date.getHours(), date.getMinutes(), date.getSeconds()]
      .map((part) => String(part).padStart(2, '0')) // 5 → '05'
      .join(':');
  }
  ```

  `toLocaleTimeString()` не подойдёт: формат зависит от настроек системы
  (`2:05:12 PM` в английской локали). Свои сообщения выделяются (`you`, цвет);

- `close()` — закрыть `readline` и стереть висящее приглашение.
  **Важно:** `quit` означает «пользователь хочет выйти». Если программа
  закрывает интерфейс сама через `close()`, `quit` испускать нельзя. Иначе
  в лабораторной 15 получится цикл: соединение закрылось → клиент вызвал
  `ui.close()` → пришёл `quit` → клиент пытается отправить `leave` в уже
  закрытое соединение. Заведите флаг `#isClosed` и в обработчике `close`
  у `readline` испускайте `quit`, только если флаг ещё не поднят;
- весь вывод — над строкой ввода (2.3) через `this.#output.write`, а без
  терминала — просто строками;
- после Enter строку `> текст` стоит стереть (`moveCursor` на строку вверх
  и `clearLine`): сервер пришлёт сообщение обратно, и оно появится
  в общей ленте.

Проверьте класс маленьким скриптом `try-ui.js`:

```js
import { TerminalUI } from './lib/terminal-ui.js';

const ui = new TerminalUI();
const timer = setInterval(() => ui.printSystem('bob joined the chat'), 1000);
ui.on('line', (text) => ui.printChat({ from: 'ann', text, ts: Date.now(), isOwn: true }));
ui.on('quit', () => {
  clearInterval(timer);
  ui.printInfo('Bye!');
  ui.close();
});
```

Начните печатать: системные сообщения появляются над строкой ввода,
а набранный текст остаётся на месте. Ctrl+C печатает `Bye!` и завершает
программу. Сделайте коммит.
