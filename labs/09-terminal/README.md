# Лабораторная 9. Терминал: `readline`, ввод и вывод

**Цель:** научиться читать ввод пользователя построчно, выводить сообщения
так, чтобы они не ломали набираемый текст, обрабатывать Ctrl+C и Ctrl+D
и отделять интерфейс от логики программы.

**Примерное время:** 2 часа.

## Теория

### Потоки ввода и вывода

У процесса три стандартных потока: `process.stdin` (ввод), `process.stdout`
(вывод) и `process.stderr` (ошибки). Ввод может прийти не только
с клавиатуры, но и из файла или от другой программы:

```bash
node app.js                      # ввод с клавиатуры
node app.js < input.txt          # ввод из файла
printf 'a\nb\n' | node app.js    # ввод из конвейера
```

`process.stdout.isTTY` равно `true`, только если вывод идёт в настоящий
терминал. Когда вывод в файл, управлять курсором и цветами бессмысленно,
и программа должна это проверять.

### `readline`

```js
import readline from 'node:readline';

const rl = readline.createInterface({ input: process.stdin, output: process.stdout });
rl.setPrompt('> ');
rl.prompt(); // показать приглашение

rl.on('line', (line) => {
  /* пользователь нажал Enter */
});
rl.on('close', () => {
  /* rl.close(), Ctrl+D или конец ввода */
});
rl.on('SIGINT', () => {
  /* Ctrl+C */
});
```

- Ctrl+D на пустой строке означает «ввод закончился»: придёт `close`.
- Ctrl+C в интерактивном терминале перехватывает `readline` и испускает
  `SIGINT`. Если на `rl` нет обработчика `SIGINT`, процесс завершается
  как обычно.
- Если ввод не из терминала, Ctrl+C до `readline` не доходит:
  сигнал получает процесс (лабораторная 14).

### Две ловушки

1. **Строки после `close()`.** Если несколько строк пришли одним куском
   (из файла или конвейера), `readline` отдаёт событием `line` и те,
   что идут после вашего `rl.close()`. А `rl.prompt()` после закрытия
   выбрасывает `ERR_USE_AFTER_CLOSE`. Решение — флаг «уже закрыто»,
   который проверяется в обработчике `line`.
2. **`rl.question` и конвейер.** `question` ждёт **следующую** строку.
   Строки, прочитанные до вызова `question`, теряются. С клавиатуры
   этого не видно, а с конвейером второй вопрос не получит ответа,
   и процесс завершится с кодом 13 («unsettled top-level await»).
   Надёжнее асинхронный итератор: `rl[Symbol.asyncIterator]()` складывает
   строки в очередь.

### Управление курсором

Терминал понимает escape-последовательности. `readline` даёт для них функции:

```js
readline.cursorTo(process.stdout, 0); // курсор в начало строки
readline.clearLine(process.stdout, 0); // стереть строку
readline.moveCursor(process.stdout, 0, -1); // на строку вверх
```

### Вывод над строкой ввода

Если просто вызвать `console.log`, пока пользователь набирает текст,
сообщение приклеится к набранному: `> привmessage from bob`. Правильно
делать так:

1. перевести курсор в начало строки и стереть её (там было `> прив`);
2. напечатать сообщение с переводом строки;
3. вызвать `rl.prompt(true)`: `readline` заново нарисует `> прив`, а `true`
   значит «сохранить позицию курсора».

### Цвета

```js
import { styleText } from 'node:util';
console.log(styleText('red', '! error'));
console.log(styleText(['bold', 'green'], 'you'));
```

`styleText` сама проверяет поток вывода и не добавляет escape-коды,
если вывод идёт не в терминал (а также если задана переменная `NO_COLOR`).

### Интерфейс отдельно от логики

Класс интерфейса умеет только показывать текст и сообщать о действиях
пользователя событиями (`line`, `quit`). Что делать с введённой строкой,
решает логика клиента. Тогда логику можно протестировать с поддельным
интерфейсом, а интерфейс заменить, не трогая логику.

## Упражнения

Решения лежат в [solution/](solution/).

### Упражнение 1. Эхо

Напишите `echo-repl.js`: каждую введённую строку печатает заглавными
буквами. Строка `exit` завершает работу, а при закрытии выводится число
строк. Проверьте интерактивно (и Ctrl+D тоже), а затем так:

```bash
printf 'hello\nпривет 😀\nexit\nignored\n' | node echo-repl.js
```

Ожидаемо: `HELLO`, `ПРИВЕТ 😀`, `Lines: 2. Bye!`, а строки `IGNORED`
и ошибок быть не должно. Сначала напишите без флага «закрыто»
и посмотрите на ловушку 1 своими глазами.

### Упражнение 2. Вопросы

Спросите имя и любимый цвет через `readline/promises` (`await rl.question(...)`).
Проверьте с клавиатуры, затем с `printf 'Ann\nblue\n' | node ask.js`
и объясните результат. Перепишите на асинхронный итератор
([ask-lines.js](solution/ask-lines.js)), чтобы работали оба способа.

### Упражнение 3. Цвета

Выведите несколько строк разными цветами. Запустите `node colors.js`
и `node colors.js > out.txt`. Откройте `out.txt`: есть ли там escape-коды?

### Упражнение 4. Часы над строкой ввода

Каждую секунду печатайте `[время] tick` **над** строкой ввода. Начните
набирать текст: он не должен перемешиваться с тиками. Введённую строку
тоже печатайте над приглашением. При закрытии `readline` остановите
таймер, иначе процесс не завершится. Затем сравните с наивным
`console.log` вместо `printAbovePrompt`.

### Упражнение 5. Подтверждение выхода

На Ctrl+C спрашивайте `Really quit? (y/n)` и выходите только при `y`.

## Шаг проекта

Создайте `lib/terminal-ui.js` с классом `TerminalUI extends EventEmitter`:

- `constructor({ input = process.stdin, output = process.stdout })`;
- события: `line` (text) — введена строка; `quit` — Ctrl+C, Ctrl+D или конец ввода;
- методы `printChat({ from, text, ts, isOwn })`, `printSystem(text, ts)`,
  `printInfo(text)`, `printError(text)` в формате из раздела 6.2 ТЗ:

  ```
  [14:05:12] alice: Привет всем!
  [14:05:20] * bob joined the chat
  ```

  Время берётся из `ts`. Свои сообщения выделяются (`you`, цвет);

- `close()` — закрыть `readline` и стереть висящее приглашение;
- весь вывод — над строкой ввода (упражнение 4), а без терминала — просто строками;
- после Enter строку `> текст` стоит стереть (`moveCursor` на строку вверх
  и `clearLine`): сервер пришлёт сообщение обратно, и оно появится
  в общей ленте.

Проверьте класс маленьким скриптом: печатайте `printSystem` раз в секунду
и отвечайте `printChat` на каждую введённую строку.
