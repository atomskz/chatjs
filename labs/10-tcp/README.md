# Лабораторная 10. TCP: первое сетевое соединение

**Цель:** понять, как две программы — возможно, на разных компьютерах —
обмениваются данными: что такое адрес и порт, кто такие сервер и клиент,
как соединение устанавливается, живёт и закрывается. Научиться писать
TCP-сервер и TCP-клиент на модуле `net` и правильно обрабатывать сетевые
ошибки.

**Понадобится:** лабораторные 3, 4 и 5. Упражнения делайте в папке `sandbox-10`
с `"type": "module"`. Для сетевых примеров нужны **два окна терминала**:
в одном работает сервер, в другом — клиент (в VS Code: кнопка «+»
или «Split Terminal» на панели терминала).

**Примерное время:** 5–6 часов, два занятия.

**Как работать:** каждый пример запускайте у себя и сверяйте вывод.
В разминках сначала запишите **свой** ответ, потом запустите код и только
потом смотрите [answers.md](answers.md).

## Занятие 1. Модель сети и первый эхо-сервер

### 1.1. Зачем

Чат — это несколько программ, которые разговаривают друг с другом: один
сервер и много клиентов, часто на разных компьютерах. Чтобы программа
могла отправить данные другой программе, нужно знать, **где** та находится,
и договориться, **как** передавать данные. Этим и занимается сеть.

**Аналогия: многоквартирный дом.**

- **IP-адрес** — адрес дома, то есть компьютера в сети: `192.168.1.10`.
- **Порт** — номер квартиры, то есть конкретной программы на этом компьютере:
  `5000`. На одном компьютере работает много сетевых программ, и порт
  говорит, какой из них предназначены данные.
- **Сервер** — жилец, который сидит дома и ждёт гостей. Говорят, что
  сервер **слушает** порт.
- **Клиент** — гость, который приходит по адресу и звонит в нужную квартиру.
  Клиент **подключается** к адресу и порту.

**Аналогия: телефонный звонок.** TCP — это не письмо, брошенное в ящик,
а телефонный разговор:

1. набрали номер и дождались ответа — **соединение установлено**;
2. говорят оба и в любом порядке — **обмен данными в обе стороны**;
3. сказали «до свидания» — **штатное закрытие**;
4. связь оборвалась на полуслове — **обрыв**.

TCP гарантирует, что всё сказанное дойдёт без потерь и в том же порядке.

### 1.2. Адреса и порты

| адрес                     | что значит                                                          |
| ------------------------- | ------------------------------------------------------------------- |
| `127.0.0.1`, `localhost`  | «этот же компьютер» (loopback). Удобно, когда сервер и клиент рядом |
| `::1`                     | то же самое в новой версии протокола, IPv6                          |
| `192.168.x.x`, `10.x.x.x` | адрес компьютера в домашней или офисной сети                        |

- Порт — число от 1 до 65535. Порты до 1024 заняты «известными» службами
  (80 — веб, 443 — защищённый веб), поэтому для своих программ берут
  что-то вроде 3000, 5000, 8080.
- Один порт на одном адресе может слушать только **одна** программа.
  Вторая получит ошибку «порт занят».
- `localhost` — это имя, а не адрес: система превращает его в `::1` или
  `127.0.0.1`.

### 1.3. Разобранный пример: эхо-сервер и клиент

Эхо-сервер отвечает тем же, что ему прислали. Это самая простая сетевая
программа, и на ней видны все этапы жизни соединения.

**Сервер** — `server.js`:

```js
import net from 'node:net';

const server = net.createServer((socket) => {
  // эта функция вызывается для КАЖДОГО нового клиента
  console.log('client connected');
  socket.on('data', (chunk) => {
    console.log(`got: ${chunk}`);
    socket.write(`echo: ${chunk}`); // ответить этому клиенту
  });
  socket.on('end', () => console.log('client said: no more data'));
  socket.on('error', (error) => console.log(`error: ${error.code}`));
  socket.on('close', () => console.log('connection closed'));
});

server.listen(5000, () => console.log('listening on port 5000'));
```

**Клиент** — `client.js`:

```js
import net from 'node:net';

const socket = net.connect({ host: '127.0.0.1', port: 5000 });

socket.on('connect', () => {
  console.log('connected');
  socket.write('hello');
});
socket.on('data', (chunk) => {
  console.log(`server says: ${chunk}`);
  socket.end(); // больше писать не будем
});
socket.on('close', () => console.log('closed'));
```

**Запуск.** В первом терминале `node server.js`, во втором — `node client.js`:

| шаг | терминал 1 (сервер)         | терминал 2 (клиент)        | что произошло                                     |
| --- | --------------------------- | -------------------------- | ------------------------------------------------- |
| 1   | `listening on port 5000`    |                            | сервер занял порт и ждёт                          |
| 2   | `client connected`          | `connected`                | клиент подключился; у каждого появился свой сокет |
| 3   | `got: hello`                |                            | клиент написал `hello`, сервер получил            |
| 4   |                             | `server says: echo: hello` | сервер ответил, клиент получил                    |
| 5   | `client said: no more data` |                            | клиент вызвал `end()` — «больше писать не буду»   |
| 6   | `connection closed`         | `closed`                   | обе стороны закрыли соединение                    |

Сервер при этом **продолжает работать**: запустите клиент ещё раз — всё
повторится. Остановить сервер можно Ctrl+C.

Что здесь важно:

- **сокет** (socket) — объект, через который идёт одно соединение. У сервера
  сокетов столько, сколько подключённых клиентов: функция в `createServer`
  получает новый сокет на каждое подключение;
- и на сервере, и у клиента сокет устроен одинаково: в него пишут через
  `write`, а из него читают событием `data`. Это **двусторонний поток**;
- всё общение — события (лабораторная 5), поэтому код не ждёт данных
  «в лоб», а реагирует, когда они пришли.

### 1.4. Жизнь соединения

```
 клиент                                          сервер
   │                                               │  listen(5000) — ждёт
   │  net.connect ──── «можно подключиться?» ────► │
   │  ◄─────────────── «да» ────────────────────── │  'connection' → новый socket
   │  'connect'                                    │
   │                                               │
   │  write('hello') ──────── данные ────────────► │  'data'
   │  ◄────────────────────── данные ───────────── │  write('echo: hello')
   │  'data'                                       │
   │                                               │
   │  end() ───────── FIN «больше не пишу» ──────► │  'end'
   │  ◄────────────── FIN ──────────────────────── │  (закрывает свою сторону сам)
   │  'close'                                      │  'close'
```

События сокета:

| событие   | когда                                                                   |
| --------- | ----------------------------------------------------------------------- |
| `connect` | (у клиента) соединение установлено                                      |
| `data`    | пришёл очередной кусок байтов                                           |
| `end`     | собеседник сказал «больше писать не буду» (TCP FIN)                     |
| `error`   | ошибка: `ECONNRESET`, `EPIPE`... Без обработчика процесс упадёт         |
| `close`   | сокет закрыт окончательно; приходит **всегда**, после `end` или `error` |

Обработчик `close` получает `hadError` — `true`, если сокет закрылся из-за ошибки.

### 1.5. Байты, а не текст

`chunk` в событии `data` — это не строка, а `Buffer`: набор байтов
(подробно — в лабораторной 11). Если напечатать его как есть, вы увидите
байты:

```js
console.log(Buffer.from('hello')); // <Buffer 68 65 6c 6c 6f>
```

Превратить байты в текст можно через `chunk.toString()`, `String(chunk)`
или шаблонную строку `` `got: ${chunk}` ``: все три декодируют байты как UTF-8.
Методу `write` можно передавать и строку, и `Buffer`.

Один `chunk` — это **не обязательно одно сообщение**: он может содержать
полсообщения или несколько сообщений сразу. Пока это не важно,
а в лабораторной 11 станет главной темой.

### 1.6. Кто есть кто: адреса сокета

У каждого конца соединения есть свой адрес и порт:

| свойство                                    | что это                                                                    |
| ------------------------------------------- | -------------------------------------------------------------------------- |
| `socket.remoteAddress`, `socket.remotePort` | адрес и порт **собеседника** (на сервере — клиента)                        |
| `socket.localAddress`, `socket.localPort`   | адрес и порт **нашего** конца (у клиента порт выдаёт ОС, например `64540`) |
| `server.address()`                          | что слушает сервер: `{ address: '::', family: 'IPv6', port: 5000 }`        |

```js
const name = `${socket.remoteAddress}:${socket.remotePort}`; // '::ffff:127.0.0.1:64540'
console.log(`connected: ${name}`);
```

Адрес `::ffff:127.0.0.1` — это обычный IPv4-адрес `127.0.0.1`, записанный
в форме IPv6. Так бывает, когда сервер слушает «всё сразу» (2.6).

### 1.7. Клиент чуть подробнее

```js
import { once } from 'node:events';
import net from 'node:net';

const socket = net.connect({ host: '127.0.0.1', port: 5000 });
await once(socket, 'connect'); // ждём подключения — или исключение, если не вышло
socket.write('hello\n');
```

`await once(socket, 'connect')` (лабораторная 5) удобен тем, что ошибку
подключения можно поймать обычным `try/catch`. Перед записью в сокет,
который мог уже закрыться, проверяют `socket.writable`: запись
в закрытый сокет — ошибка.

### 1.8. Инструменты

- `nc localhost 5000` (netcat) — подключиться к серверу и печатать вручную.
  Есть в Linux и macOS. В Windows его нет, поэтому в упражнении 3 вы
  напишете замену — `nc.js`.
- Кто какие порты слушает: `netstat -ano | findstr :5000` в Windows,
  `lsof -i :5000` в macOS и Linux. Так можно найти программу, которая
  заняла порт, и её номер процесса (PID).

## Занятие 2. Ошибки, закрытие и адреса

### 2.1. Где что может сломаться

У сетевой программы ошибки бывают на каждом этапе. Удобно знать, на каком
этапе какая:

```
сервер: listen ──────► EADDRINUSE (порт занят), EACCES (нет прав)

клиент: connect ─────► ECONNREFUSED (никто не слушает), ENOTFOUND (нет такого имени),
                       ETIMEDOUT (никто не отвечает), EHOSTUNREACH / ENETUNREACH (нет маршрута)

оба:    обмен ───────► ECONNRESET (собеседник оборвал), EPIPE (пишем в закрытое)
```

**Разобранный пример: порт занят.** Запустите сервер из 1.3, а во втором
терминале — ещё раз ту же команду:

```
node:events:487
      throw er; // Unhandled 'error' event
      ^

Error: listen EADDRINUSE: address already in use :::5000
Emitted 'error' event on Server instance at:
  code: 'EADDRINUSE',
  ...
```

Это сразу две новости. Первая — сам код `EADDRINUSE`: порт уже занят.
Вторая — `Unhandled 'error' event`: у сервера нет обработчика `error`,
и программа упала (лабораторная 5). Правильная версия ловит ошибку
и печатает понятное сообщение:

```js
import { once } from 'node:events';
import net from 'node:net';

const server = net.createServer(/* ... */);
server.listen(5000);
try {
  await once(server, 'listening'); // отклонится, если раньше придёт 'error'
  console.log('listening on port 5000');
} catch (error) {
  if (error.code === 'EADDRINUSE') {
    console.error('Port 5000 is already in use');
  } else {
    console.error(`Cannot listen: ${error.message}`);
  }
  process.exitCode = 1;
}
```

**Разобранный пример: никто не слушает.** Запустите клиент на порт 5001,
где сервера нет:

```
Error: connect ECONNREFUSED 127.0.0.1:5001
Emitted 'error' event on Socket instance at:
  code: 'ECONNREFUSED',
  ...
```

Сетевые ошибки:

| код                           | где      | значит                                             |
| ----------------------------- | -------- | -------------------------------------------------- |
| `EADDRINUSE`                  | `listen` | порт занят другим процессом                        |
| `EACCES`                      | `listen` | нет прав (порты ниже 1024 в Linux и macOS)         |
| `ECONNREFUSED`                | клиент   | на этом адресе и порте никто не слушает            |
| `ENOTFOUND`                   | клиент   | имя хоста не найдено                               |
| `ETIMEDOUT`                   | клиент   | не дождались ответа                                |
| `EHOSTUNREACH`, `ENETUNREACH` | клиент   | нет маршрута до этого адреса или сети              |
| `ECONNRESET`                  | оба      | собеседник оборвал соединение                      |
| `EPIPE`                       | оба      | запись в соединение, которое собеседник уже закрыл |

### 2.2. Обработчик `error` у сокета обязателен

**Разобранный пример.** Сервер без обработчика `error` на сокете
([solution/fragile-server.js](solution/fragile-server.js)) и клиент,
который обрывает соединение «грубо», как упавшая программа
([solution/reset-client.js](solution/reset-client.js)):

```
listening on port 5000
client connected
node:events:487
      throw er; // Unhandled 'error' event
      ^

Error: read ECONNRESET
Emitted 'error' event on Socket instance at:
```

Один клиент оборвал связь — и упал весь сервер, со всеми остальными
клиентами. Одна строка `socket.on('error', ...)` превращает это в запись
в логе. Причину ошибки всё равно удобно узнавать в `close`, поэтому
обработчик `error` может быть совсем простым.

### 2.3. Закрытие: штатное, обрыв, тишина

**Штатно: `end`.** `socket.end()` дописывает то, что в буфере, и отправляет
FIN — «больше писать не буду».

- `socket.end(data)` — то же, что `write(data)`, а затем `end()`.
- После `end()` писать в сокет уже нельзя (`write after end`, код
  `ERR_STREAM_WRITE_AFTER_END`), но **читать можно**: ответы собеседника
  приходят, пока он не закроет свою сторону. Поэтому клиент может отправить
  запрос через `end(text)` и всё равно получить ответ.
- Собеседник получит `end`. В Node.js сокет по умолчанию сразу закрывает
  и свою сторону (опция `allowHalfOpen: false`). Если создать сокет
  с `allowHalfOpen: true`, после `end` от собеседника он сможет ещё писать —
  это «полуоткрытое» соединение, оно понадобится в лабораторной 14.

**Немедленно: `destroy`.** `socket.destroy()` закрывает сразу: данные
в буфере пропадут, собеседник может получить `ECONNRESET`.

Три сценария, которые увидит сервер:

| что случилось у клиента         | что придёт на сервер                                                                       |
| ------------------------------- | ------------------------------------------------------------------------------------------ |
| вызвал `end()`                  | `end`, затем `close`                                                                       |
| процесс упал, закрыли терминал  | ОС закроет сокет: `end` или `error` `ECONNRESET`, затем `close`                            |
| пропала сеть (выдернули кабель) | **ничего**. Сервер узнает об этом, только когда попробует что-то отправить или по таймауту |

Первые два случая заканчиваются событием `close`. Поэтому «клиент ушёл»
удобно обрабатывать в одном месте — в `close`. Третий случай — причина,
зачем в серьёзных серверах есть проверки «жив ли собеседник» (лабораторная 12,
`ping`/`pong`).

### 2.4. Таймаут подключения

Если сервер по адресу не отвечает, ОС сдаётся не скоро: около 20 секунд
в Windows и до двух минут в Linux. Ждать столько пользователь не станет.
Опция `timeout` у `net.connect` — это **таймаут простоя**: сокет испустит
событие `timeout`, если по нему ничего не происходит N миллисекунд.
Ошибку он не создаёт и сокет не закрывает: это делаем мы сами.

```js
const socket = net.connect({ host, port, timeout: 5000 });
socket.once('timeout', () => {
  // destroy(error) закрывает сокет и испускает 'error' с этой ошибкой,
  // поэтому промис once(socket, 'connect') ниже отклонится.
  const error = new Error('Connection timed out');
  error.code = 'ETIMEDOUT';
  socket.destroy(error);
});
await once(socket, 'connect');
socket.setTimeout(0); // подключились: дальше соединение может молчать сколько угодно
```

Без `setTimeout(0)` соединение чата, в котором 5 секунд никто ничего
не пишет, разорвалось бы «по таймауту».

### 2.5. `localhost` и `AggregateError`

Имя `localhost` указывает сразу на два адреса: `::1` (IPv6) и `127.0.0.1`
(IPv4). Node.js пробует оба (это называется Happy Eyeballs). Если не подошёл
ни один, приходит `AggregateError` — ошибка, внутри которой список ошибок:

```js
error.code; // 'ECONNREFUSED' — код первой ошибки (не во всех версиях Node.js)
error.message; // '' — пустая строка!
error.errors; // [Error: connect ECONNREFUSED ::1:5000, Error: connect ECONNREFUSED 127.0.0.1:5000]
```

Поэтому код ошибки надёжнее брать так: `error.code ?? error.errors?.[0]?.code`.
И не стоит рассчитывать на `error.message`: у `AggregateError` он пустой.

### 2.6. Куда слушать: `127.0.0.1`, `0.0.0.0`, `::`

| `server.listen(port, host)` | кто может подключиться                            |
| --------------------------- | ------------------------------------------------- |
| `'127.0.0.1'`               | только программы на этом же компьютере (loopback) |
| `'0.0.0.0'`                 | все по IPv4, в том числе с других машин сети      |
| не указан                   | все интерфейсы и по IPv4, и по IPv6 (`::`)        |

Сервер на `127.0.0.1` — как квартира, дверь которой открывается только
изнутри дома: соседи по сети не достучатся. Чтобы к серверу подключались
с других компьютеров, слушают без хоста или на `0.0.0.0`.

**Порт 0.** `server.listen(0)` просит ОС выдать любой свободный порт.
Узнать, какой именно, можно через `server.address().port`. Так делают
в тестах, чтобы не зависеть от занятых портов.

**Остановка сервера.** `server.close()` перестаёт принимать новые
подключения, но уже открытые сокеты не трогает. Сервер окончательно
закроется (и его колбэк `close` сработает), когда закроется последний
из них. `server.listening` — `true`, пока сервер слушает порт.

## Упражнения

Решения лежат в [solution/](solution/). Упражнения 1–3 — к первому занятию,
4–7 — ко второму.

### Упражнение 1. Эхо-сервер

Напишите `echo-server.js [port] [host]`. Сервер отвечает `echo: <то, что прислали>`
и логирует подключение, `end`, ошибки и `close` с адресом клиента
(`remoteAddress:remotePort`). При старте он выводит, какой адрес и порт
реально слушает (`server.address()`), а при занятом порте печатает
понятное сообщение и завершается с кодом 1 (2.1).

### Упражнение 2. Свой клиент

Напишите `client.js <host> <port> <text>`. Он подключается, печатает
`connected from <localAddress>:<localPort>`, отправляет строку, печатает
ответ сервера и завершается. Отправьте текст и закройте свою сторону одним
вызовом `socket.end(text)`. Поставьте таймаут подключения 3 секунды,
как в 2.4 (`timeout: 3000`): он понадобится в упражнении 4.

**Проверка** (сервер в одном терминале, клиент — в другом):

```bash
node echo-server.js 5000
node client.js 127.0.0.1 5000 "hello, привет"
node client.js localhost 5000 hi                # с какого адреса пришёл клиент? (см. лог сервера)
```

Вывод клиента:

```
connected from 127.0.0.1:64540
server says: echo: hello, привет
connection closed
```

### Упражнение 3. Интерактивный клиент `nc.js`

Клиент из упражнения 2 отправляет одну строку и выходит. Для следующих
упражнений нужен интерактивный: всё, что вы набираете, уходит на сервер,
а ответы печатаются. В Linux и macOS для этого есть `nc`, а в Windows его
нет. Напишите свой `nc.js <host> <port>` — хватит десяти строк:

- после `connect`: `process.stdin.pipe(socket)` (ввод → сервер)
  и `socket.pipe(process.stdout)` (сервер → экран). `pipe` соединяет два
  потока и сам закрывает сокет (`end`), когда ввод закончился;
- на `error` — напечатать код ошибки и поставить код выхода 1;
- на `close` — `process.exit()`: `stdin` может остаться открытым и держать процесс.

**Проверка:** `node nc.js localhost 5000`, наберите пару строк — эхо-сервер
отвечает на каждую. Через конвейер: `printf 'a\nb\n' | node nc.js localhost 5000`.
Готовый вариант — [solution/nc.js](solution/nc.js). Дальше везде, где
написано `nc`, можно использовать `node nc.js`.

### Упражнение 4. Ошибки

Добейтесь каждой ошибки и выведите понятное сообщение с кодом выхода 1:

- запустите второй сервер **той же командой** на том же порту — `EADDRINUSE`.
  (В Windows сервер на `::` и сервер на `0.0.0.0` с одним портом могут
  работать одновременно, поэтому команды должны совпадать);
- подключитесь к порту, где никто не слушает, — `ECONNREFUSED`.
  Попробуйте и `127.0.0.1`, и `localhost` и сравните, какие ошибки пришли;
- подключитесь к `no-such-host.invalid` — `ENOTFOUND`;
- подключитесь к адресу, который не отвечает (например, `10.255.255.1`), —
  `ETIMEDOUT` через 3 секунды благодаря таймауту из 2.4. В некоторых сетях
  вместо этого сразу придёт `EHOSTUNREACH` или `ENETUNREACH` («нет маршрута») —
  это тоже правильный результат.

Затем — обрыв. Запустите [solution/fragile-server.js](solution/fragile-server.js)
и подключитесь к нему [solution/reset-client.js](solution/reset-client.js).
Сервер упадёт с `ECONNRESET`. Раскомментируйте обработчик `error`
и повторите: теперь сервер пишет ошибку в лог и работает дальше.

Наконец, подключитесь к своему эхо-серверу через `nc.js` и закройте окно
терминала, не отключаясь. Что сервер напечатал в логе?

### Упражнение 5. Рассылка всем

Напишите `broadcast-server.js`: сервер хранит все сокеты в `Set` и пересылает
то, что прислал один клиент, всем остальным с подписью
`[адрес:порт]`. При подключении и отключении выводится число клиентов.
Проверьте с двумя-тремя `nc.js` в разных окнах терминала. Это шаг 2 из ТЗ,
только на TCP — первый настоящий «чат».

### Упражнение 6. Порт 0 и адрес

Запустите три сервера на порту `0`: без хоста, на `0.0.0.0` и на
`127.0.0.1`, и выведите `server.address()` каждого.

### Упражнение 7. Подключение из локальной сети

1. Узнайте IP своей машины: `ipconfig` в Windows (строка «IPv4-адрес»),
   `ip addr` в Linux, `ipconfig getifaddr en0` в macOS. Обычно он вида
   `192.168.x.x` или `10.x.x.x`.
2. Запустите эхо-сервер на `127.0.0.1` и подключитесь `node nc.js <ваш IP> 5000`
   (лучше с другого компьютера или телефона в той же сети). Ожидаемо:
   `ECONNREFUSED` или таймаут — сервер слушает только loopback.
3. Запустите эхо-сервер без хоста и повторите — подключение проходит.

**Брандмауэр.** При первом запуске сервера Windows спросит, разрешить ли
`node.exe` доступ к сети. Разрешите для **частных** сетей. Если сеть
в Windows помечена как «Общедоступная», входящие подключения будут
заблокированы: переключите профиль сети на «Частная» в параметрах Windows.
Проверить, открыт ли порт, можно с другого Windows-компьютера:
`Test-NetConnection 192.168.1.10 -Port 5000` (PowerShell).

## Типичные ошибки

| что видите                                                   | почему                                                                                   | что делать                                                            |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| `EADDRINUSE` при запуске сервера                             | порт занят — часто вашим же сервером в другом окне терминала                             | остановить его (Ctrl+C) или найти через `netstat`/`lsof`; другой порт |
| `ECONNREFUSED`                                               | сервер не запущен, другой порт или сервер слушает `127.0.0.1`, а вы стучитесь по IP сети | проверить, что сервер работает, порт и адрес                          |
| сервер упал: `read ECONNRESET ... Unhandled 'error' event`   | у сокета нет обработчика `error`                                                         | `socket.on('error', ...)` у каждого сокета                            |
| сервер упал: `listen EADDRINUSE ... Unhandled 'error' event` | у сервера нет обработчика ошибки `listen`                                                | `await once(server, 'listening')` в `try/catch` (2.1)                 |
| в логе `<Buffer 68 65 6c 6c 6f>` вместо текста               | напечатан `Buffer` как есть                                                              | `chunk.toString()` или шаблонная строка                               |
| `ERR_STREAM_WRITE_AFTER_END: write after end`                | `write` после `end()`                                                                    | писать до `end`, проверять `socket.writable`                          |
| клиент не завершается                                        | соединение не закрыто, или `stdin` держит процесс                                        | `socket.end()`; в `nc.js` — `process.exit()` на `close`               |
| подключение висит ~20 секунд, потом `ETIMEDOUT`              | по адресу никто не отвечает, а свой таймаут не задан                                     | таймаут подключения (2.4); проверить адрес                            |
| с другого компьютера не подключиться                         | сервер на `127.0.0.1`, брандмауэр или «общедоступная» сеть                               | слушать без хоста; разрешить `node.exe`; профиль «Частная»            |
| кириллица иногда превращается в `�`                          | кусок данных разрезал букву пополам                                                      | это тема лабораторной 11 (`StringDecoder`)                            |

## Шаг проекта

Своего сетевого сервера в `chat/` пока нет (он появится в лабораторной 13),
поэтому функции для ошибок проверим в песочнице:

1. Импортируйте `describeListenError` из `chat/lib/errors.js` (лабораторная 3)
   в свой `echo-server.js` (`import { describeListenError } from '../chat/lib/errors.js'` —
   путь зависит от того, где лежит песочница) и выводите её результат при ошибке `listen`.
   Проверьте на `EADDRINUSE`. Ошибку `EACCES` можно получить в Linux и macOS
   на порту ниже 1024 (`node echo-server.js 80`). В Windows такого запрета нет.
2. Добавьте в `chat/lib/errors.js` функцию `export function describeConnectError(error)`:

   | код                      | результат                                                                      |
   | ------------------------ | ------------------------------------------------------------------------------ |
   | `ECONNREFUSED`           | `connection refused. Is the server running on this host and port?`             |
   | `ETIMEDOUT`              | `connection timed out. Check the address and your network.`                    |
   | `ENOTFOUND`, `EAI_AGAIN` | `host not found. Check the address.`                                           |
   | любой другой             | `error.message \|\| code` — у `AggregateError` текст пустой, тогда хотя бы код |

   Код берите с учётом `AggregateError` (2.5): `error.code ?? error.errors?.[0]?.code`.
   (`EAI_AGAIN` — временная ошибка DNS, например когда нет интернета.)
   Подключите её в `client.js` из упражнения 2 и проверьте на ошибках из упражнения 4.

3. Запомните, где лежит ваш `nc.js` из упражнения 3. В лабораторных 11–15
   команда `node nc.js localhost 5000` значит «запустите свой `nc.js`»,
   например `node ../sandbox-10/nc.js localhost 5000` из папки `chat/`.
   Копировать его в `chat/` не нужно: проверка в лабораторной 15 ищет
   `net` только в `transport/`.
