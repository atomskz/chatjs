# Лабораторные работы: консольный чат на Node.js

Шестнадцать лабораторных (с нулевой) по порядку разбирают все технологии и приёмы,
из которых состоит чат из этого репозитория. После них у вас будет
свой чат, собранный с нуля по [техническому заданию](15-chat/chat-tz.md),
и понимание каждой его строки.

Если вы раньше писали код только в браузере или онлайн-редакторе и почти
не работали в терминале, начните с [лабораторной 0](00-environment/):
терминал, запуск программ на Node.js, чтение ошибок, отладчик и git.

## Как устроена каждая лабораторная

- **Теория** — с примерами кода. Каждая тема построена так: «зачем» →
  разобранный пример по шагам с настоящим выводом → короткая разминка.
  В конце лабораторной — таблица типичных ошибок.
- **Упражнения** — маленькие самостоятельные программы в отдельной папке-песочнице.
  Решения лежат в папке `solution/` каждой лабораторной. Сначала решите сами.
- **Шаг проекта** — кусок вашего собственного чата. Проект `chat/`
  создаётся в лабораторной 1 в отдельной папке и растёт от лабораторной
  к лабораторной. Удобно делать по коммиту на каждую.
- **Контрольные вопросы** — проверьте, что поняли, а не только сделали.
  Ответы на вопросы и разминки лежат в `answers.md` каждой лабораторной.
- **Где это в эталонном проекте** — ссылки на код этого репозитория
  и на теги `step-N` в его истории.

## Что нужно

- Node.js 22.13 или новее, лучше 24 LTS (`node --version`). Более старые
  версии 22.x не подойдут: им не хватает возможностей, которые нужны ESLint.
- Редактор кода и git.
- Терминал. Команды в лабораторных написаны для bash (Linux, macOS).
- Знание основ JavaScript: переменные, функции, условия, циклы, массивы
  и объекты. Более новый синтаксис, который встречается в проекте
  (`?.`, `??`, деструктуризация, `...`, классы), собран
  в [шпаргалке](js-cheatsheet.md).

### Windows

Проще всего работать в **Git Bash**: он ставится вместе с
[Git for Windows](https://git-scm.com/download/win), и в нём работают
все команды из лабораторных. Вместо `nc` используйте маленький клиент
[nc.js](10-tcp/solution/nc.js) из лабораторной 10: `node nc.js localhost 5000`.
Интерактивные программы (ввод с клавиатуры, Ctrl+C) в Git Bash иногда
не видят терминал. Подробности — в лабораторной 9.

Если вы работаете в PowerShell, вот замены:

| bash                             | PowerShell                                    |
| -------------------------------- | --------------------------------------------- |
| `echo $?` (код выхода)           | `$LASTEXITCODE`                               |
| `printf 'a\nb\n' \| node x.js`   | `"a", "b" \| node x.js`                       |
| `node x.js < input.txt`          | `Get-Content input.txt \| node x.js`          |
| `rm -rf node_modules`            | `Remove-Item -Recurse -Force node_modules`    |
| `sleep 1`                        | `Start-Sleep 1`                               |
| `curl -i http://localhost:5000/` | `curl.exe -i http://localhost:5000/`          |
| `nc localhost 5000`              | `node nc.js localhost 5000` (лабораторная 10) |

Три ловушки PowerShell:

- в Windows PowerShell 5.1 `curl` — это другая команда (`Invoke-WebRequest`).
  Настоящий curl есть в Windows 10 и 11, его вызывают как `curl.exe`;
- при передаче текста через `|` Windows PowerShell 5.1 может испортить кириллицу
  и эмодзи или добавить в начало невидимый символ BOM. Для упражнений
  с конвейером берите Git Bash или PowerShell 7 (`pwsh`);

- если `npm` пишет «выполнение сценариев отключено в этой системе»,
  выполните один раз `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`
  или вызывайте `npm.cmd` вместо `npm`;
- в Windows PowerShell 5.1 перенаправление `node app.js > out.txt` пишет
  файл в кодировке UTF-16. Для проверок в лабораторных это не важно,
  но открывайте такой файл редактором, а не `cat` из Git Bash.

## Как устроены упражнения

Каждая лабораторная предлагает завести для упражнений отдельную папку-песочницу
(`sandbox-02`, `sandbox-03`...). В каждой песочнице нужен `package.json`
со строкой `"type": "module"`, иначе не заработают `import`
(лабораторная 1). Проще всего скопировать `package.json` из `sandbox-01`
или продолжать работать в одной песочнице.

## История эталонного проекта

Эталонный чат собран коммитами по шагам ТЗ, и каждый шаг отмечен тегом
`step-0`…`step-10`. Теги — это история **автора**, а не состояние
проекта после лабораторной N: на шаге 3 у автора уже есть и транспорт,
и логика сервера, а в лабораторных они появятся позже.

**Не делайте `git checkout step-N` в этой папке**: в старых тегах ещё нет
папки `labs/`, и git уберёт её из рабочей копии (она вернётся после
`git switch main`). Смотрите историю так:

```bash
git log --oneline --reverse          # все шаги по порядку
git show step-3 --stat               # какие файлы изменились на шаге 3
git show step-3:lib/cli.js           # файл в том виде, каким он был на шаге 3
git diff step-2 step-3               # что изменилось между шагами
git worktree add ../chatjs-step-3 step-3   # шаг 3 целиком в отдельной папке
```

Если вы скачали репозиторий архивом ZIP, тегов у вас нет. Тогда смотрите
историю на странице репозитория: в списке тегов или в истории коммитов.

## Как запускать решения

Решения пользуются модулями эталонного проекта и пакетами из его
`node_modules`, поэтому сначала установите зависимости в корне репозитория:

```bash
npm install
```

Обычные решения запускаются через `node`, тесты — через `node --test`:

```bash
node labs/04-async/solution/parallel.js
node --test "labs/07-testing/solution/*.test.js"
```

Папки `tests/` в лабораторных 8 и 15 — приёмочные тесты для **вашего** проекта:
их копируют в `chat/test/`, и пути импорта в них рассчитаны на структуру `chat/`.
Отсюда они не запускаются.

`npm test` эталонного проекта решения лабораторных не запускает.
`npm run lint` и `npm run format:check` проверяют и их.

## Для преподавателя

- Время указано примерное, для студента, который делает упражнения сам.
  Вся программа занимает 45–55 часов для студента, который уже немного
  программировал, и заметно больше для новичка, который знает только синтаксис.
- Самая важная проверка архитектуры — в лабораторных 13 и 15: тесты
  эталонного проекта должны пройти на коде студента без правок.
- Самые большие лабораторные — 8 (сервер) и 15 (клиент). Они разбиты на ступени,
  у каждой ступени свой готовый тест в папке `tests/`. Удобно принимать
  их по ступеням.
- Интерактивные упражнения (ввод в терминале во время входящих сообщений,
  Ctrl+C) нельзя проверить автотестами. Их стоит посмотреть вживую.
