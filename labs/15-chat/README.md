# Лабораторная 15. Итоговая: собираем чат

**Цель:** собрать из частей, написанных в прошлых лабораторных, полный
чат по [техническому заданию](chat-tz.md) и сдать его по критериям приёмки.
По дороге освоить конечный автомат — способ писать код, поведение
которого зависит от этапа работы.

**Понадобится:** проект `chat/` после лабораторных 1–14.

**Примерное время:** 10–12 часов: два занятия, упражнения и шаг проекта
из пяти частей.

**Как работать:** каждый пример запускайте у себя и сверяйте вывод.
В разминках сначала запишите **свой** ответ, потом проверьте и только
потом смотрите [answers.md](answers.md).

## Занятие 1. Конечный автомат

### 1.1. Зачем

Осталось написать клиент. С виду он простой: отправить `join`, показывать
сообщения, отправлять ввод. Но одно и то же событие значит для него
разное в зависимости от того, **на каком этапе** он находится:

- `error` от сервера до входа — «войти не удалось, выходим с кодом 1»,
  а после входа — «это сообщение не прошло, показать и работать дальше»;
- закрытие соединения после `/quit` — штатный выход с кодом 0, а без `/quit` —
  обрыв, «Connection to server lost» и код 1;
- второй `/quit` подряд не должен отправить второй `leave`.

Первое, что приходит в голову, — завести флаги:

```js
let isJoined = false;
let isQuitting = false;
let isFailed = false;
```

Три флага — это 2 × 2 × 2 = 8 сочетаний, а осмысленных этапов только
четыре. Что значит `isJoined && isFailed`? Такое сочетание не должно
появляться, но код его не запрещает: забыли сбросить один флаг — и клиент
оказался в «невозможном» состоянии. Каждый `if` приходится писать так,
чтобы он учитывал все флаги сразу.

Надёжнее хранить **одно** поле, которое говорит, где мы сейчас:
`#state = 'joining' | 'joined' | 'leaving' | 'failed'`. Невозможных
сочетаний нет, а каждое решение — это вопрос «что делать в этом состоянии
при этом событии».

### 1.2. Разобранный пример: турникет в метро

Конечный автомат — это:

- **состояния** — конечный список этапов, в каждый момент автомат ровно в одном;
- **события** — то, что с ним происходит снаружи;
- **переходы** — для каждой пары «состояние + событие»: что сделать и в какое
  состояние перейти.

Классический пример — турникет. У него два состояния (`locked`, `unlocked`)
и два события: опустили монету (`coin`) и толкнули (`push`):

| состояние  | событие | действие               | новое состояние |
| ---------- | ------- | ---------------------- | --------------- |
| `locked`   | `coin`  | открыться              | `unlocked`      |
| `locked`   | `push`  | не пустить             | `locked`        |
| `unlocked` | `coin`  | вернуть монету         | `unlocked`      |
| `unlocked` | `push`  | пропустить и закрыться | `locked`        |

```
          coin
   ┌─────────────────┐
   │                 ▼
locked ◄────────── unlocked
 │  ▲     push      │  ▲
 └──┘               └──┘
 push               coin
```

В коде автомат — это поле состояния и `switch` по нему в каждом событии:

```js
class Turnstile {
  #state = 'locked';

  get state() {
    return this.#state;
  }

  coin() {
    switch (this.#state) {
      case 'locked':
        this.#state = 'unlocked';
        return 'unlocked, come in';
      case 'unlocked':
        return 'already unlocked, coin returned';
    }
  }

  push() {
    switch (this.#state) {
      case 'locked':
        return 'locked, insert a coin';
      case 'unlocked':
        this.#state = 'locked';
        return 'passed, locked again';
    }
  }
}

const turnstile = new Turnstile();
for (const event of ['push', 'coin', 'coin', 'push', 'push']) {
  const before = turnstile.state;
  const result = turnstile[event]();
  console.log(before.padEnd(9), '+', event.padEnd(5), '→', turnstile.state.padEnd(9), result);
}
```

```
locked    + push  → locked    locked, insert a coin
locked    + coin  → unlocked  unlocked, come in
unlocked  + coin  → unlocked  already unlocked, coin returned
unlocked  + push  → locked    passed, locked again
locked    + push  → locked    locked, insert a coin
```

Разбор:

- `get state()` — геттер: читается как поле, `turnstile.state`, без скобок,
  а записать в него снаружи нельзя. Так состояние видно, но поменять его
  можно только событиями.
- `turnstile[event]()` — вызов метода по имени из строки: `turnstile['coin']()`
  то же самое, что `turnstile.coin()`.
- Каждая строка вывода — ровно одна строка таблицы переходов. Если поведение
  неправильное, сразу видно, какая строка таблицы нарушена.
- Таблицу удобно писать **до** кода: она заставляет ответить на вопрос
  «а что, если…» для каждой пары. Пустая клетка таблицы — это баг, который
  пока не случился.

### 1.3. Автомат клиента чата

Состояния:

| состояние | что значит                    |
| --------- | ----------------------------- |
| `joining` | отправили `join`, ждём ответа |
| `joined`  | в чате                        |
| `leaving` | пользователь выходит сам      |
| `failed`  | сервер отказал во входе       |

Переходы, которые зависят от состояния:

| состояние           | событие            | действие                                  | новое состояние |
| ------------------- | ------------------ | ----------------------------------------- | --------------- |
| `joining`           | пришёл `welcome`   | приветствие и список участников           | `joined`        |
| `joining`           | пришёл `error`     | `Cannot join: ...`, закрыть соединение    | `failed`        |
| `joining`, `joined` | `/quit`, Ctrl+C    | отправить `leave`, закрыть соединение     | `leaving`       |
| `joined`            | пришёл `error`     | показать ошибку                           | `joined`        |
| `leaving`           | пришёл `welcome`   | ничего (ответ опоздал)                    | `leaving`       |
| `leaving`, `failed` | `/quit`, Ctrl+C    | ничего (уже выходим)                      | без изменений   |
| `leaving`           | соединение закрыто | `Bye!`, код выхода 0                      | —               |
| `failed`            | соединение закрыто | код выхода 1                              | —               |
| `joining`, `joined` | соединение закрыто | `Connection to server lost`, код выхода 1 | —               |

```
              welcome
   joining ───────────► joined
     │  │                 │
error│  │ /quit    /quit  │
     ▼  └──────┐  ┌───────┘
   failed      ▼  ▼
     │        leaving ◄─┐ welcome (опоздал)
     │          │  └────┘
     │ close    │ close
     ▼          ▼
  код 1       код 0
```

На схеме нет одной стрелки, чтобы не загромождать её: `close` в `joining`
или `joined` — это «Connection to server lost» и код 1.

Остальные сообщения (`msg`, `system`, `users`) показываются одинаково
в любом состоянии, а ввод пользователя обрабатывается так же и до прихода
`welcome`. В таблице выше — только то, что зависит от состояния.

### 1.4. Разобранный пример: строка, которую легко забыть

Самая коварная строка таблицы — `leaving + welcome`. Представьте: клиент
отправил `join`, сервер уже ответил `welcome`, ответ летит по сети, а
пользователь в эту же секунду нажал Ctrl+C. Клиент перешёл в `leaving`
и отправил `leave`. Потом приходит опоздавший `welcome`.

Если обработчик `welcome` не смотрит на состояние и всегда переходит
в `joined`, клиент «забудет», что выходит. Соединение закроется, и
`#exitCodeOnClose` в состоянии `joined` решит, что это обрыв. Тест ступени 4
ловит именно это. Вот что он показывает, если из обработчика `welcome`
убрать проверку `if (this.#state !== 'joining') return;`:

```
✔ Ctrl+C (quit from the UI) works like /quit (2.1793ms)
✔ the server dropped the connection → "Connection to server lost", code 1 (0.9703ms)
✖ quit before welcome still exits with code 0 (0.8201ms)
✔ quit twice sends leave only once (0.9458ms)
...
✖ quit before welcome still exits with code 0 (0.8201ms)
  AssertionError [ERR_ASSERTION]: Expected values to be strictly equal:

  1 !== 0

      at TestContext.<anonymous> (file:///.../test/chat-client-4-exit.test.js:33:10)
```

Как читать (лабораторная 8, 2.2): упал один тест, ожидали код выхода `0`,
получили `1`. Строка 33 теста — `assert.equal(await exitCode, 0)`. Значит,
при закрытии соединения клиент думал, что он не в `leaving`. Кто мог
вывести его из `leaving`? Только обработчик `welcome`.

### 2.3. Транспорт — часть договорённости

Флаг `--transport` есть и у сервера, и у клиента. Протокол чата
(`join`, `msg`, ...) одинаковый, но байты по проводу ходят по-разному.
Что будет, если стороны выбрали **разные** транспорты:

**Клиент `ws`, сервер `tcp`.** Клиент отправляет HTTP-запрос рукопожатия.
TCP-сервер режет его на строки и принимает каждую за сообщение чата:

```
INFO  Connected: ::ffff:127.0.0.1:54168
WARN  Error BAD_MESSAGE for ::ffff:127.0.0.1:54168: Message is not valid JSON
WARN  Error BAD_MESSAGE for ::ffff:127.0.0.1:54168: Message is not valid JSON
...                                (всего 7 раз — по строке запроса)
INFO  Disconnected: ::ffff:127.0.0.1:54168: read ECONNRESET
```

Клиент ждал HTTP-ответ `101`, а получил строки JSON. До соединения
дело не дошло:

```
Cannot connect to 127.0.0.1:5401: Parse Error: Expected HTTP/, RTSP/ or ICE/
```

**Клиент `tcp`, сервер `ws`.** TCP-соединение устанавливается, клиент
отправляет `join` строкой JSON. HTTP-сервер видит не HTTP-запрос и отвечает
`400 Bad Request`, а затем закрывает соединение. Клиент получает строки
HTTP вместо JSON:

```
Connected to tcp://127.0.0.1:5402
! Received a malformed message from the server
! Received a malformed message from the server
! Connection to server lost
```

Код выхода в обоих случаях 1.

## Типичные ошибки

| что видите                                                     | почему                                                       | что делать                                                 |
| -------------------------------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------- |
| после `Bye!` или `Connection to server lost` клиент не выходит | `readline` держит ввод открытым                              | `ui.close()` в обработчике `close` соединения              |
| `/quit` сразу после запуска даёт `Connection to server lost`   | опоздавший `welcome` вернул клиента в `joined`               | в `welcome` переходить, только если `#state === 'joining'` |
| два `leave` подряд или ошибка после двойного Ctrl+C            | `quit()` не смотрит на состояние                             | в `leaving` и `failed` `quit()` ничего не делает           |
| после `Cannot join` клиент висит                               | в `failed` соединение не закрыто                             | `connection.close()` после ошибки входа                    |
| ошибки после входа печатаются как `Cannot join: ...`           | `error` обрабатывается без учёта состояния                   | `Cannot join` и закрытие — только в `joining`              |
| клиент падает с `SyntaxError` на мусоре от сервера             | `decode` без `try/catch`                                     | поймать и `printError('Received a malformed message ...')` |
| новый тип сообщения сервера печатает ошибку или роняет клиент  | в `switch` нет ветки `default` или в ней ошибка              | неизвестные типы молча пропускать                          |
| `Cannot connect to ...: ` с пустой причиной                    | `AggregateError` с пустым `message` (localhost: IPv4 и IPv6) | код из `error.errors[0].code`, запасной вариант — сам код  |
| `Parse Error: Expected HTTP/` при подключении                  | клиент `ws`, а сервер запущен с `--transport tcp`            | одинаковый `--transport` у обеих сторон                    |
| тест ступени висит до таймаута                                 | `run()` не отправил `join` или не подписался на `close`      | сверить `run()` с каркасом                                 |

## Шаг проекта

### Шаг 1. Логика клиента: `lib/chat-client.js`

Класс `ChatClient({ connection, ui, nick })` связывает соединение
и интерфейс, но не знает ни про WebSocket, ни про `readline`. Это самый
большой кусок курса, поэтому он, как сервер в лабораторной 8, разбит
на ступени с готовыми тестами в папке [tests/](tests/). Порядок работы
на ступени тот же: скопировать тест, запустить, увидеть, что он падает,
написать код, добиться зелёного, сделать коммит.

#### Каркас

```js
import { ClientMessage, decode, encode, validateText } from '../protocol.js';

const HELP = [
  'Commands:',
  '  /users  show online users',
  '  /quit   leave the chat (same as Ctrl+C)',
  '  /help   show this help',
].join('\n');

export class ChatClient {
  #connection;
  #ui;
  #nick;
  #state = 'joining';

  constructor({ connection, ui, nick }) {}

  /** Подписывается на события, отправляет join. Промис выполнится кодом выхода. */
  run() {
    return new Promise((resolve) => {
      // connection 'message' → #handleServerText(text)
      // connection 'close'   → посчитать код выхода, ui.close(), resolve(код)
      // ui 'line'            → #handleInput(line)
      // ui 'quit'            → this.quit()
      // и отправить ClientMessage.join(nick)
    });
  }

  quit() {} // leave + close, если состояние не leaving и не failed
  #exitCodeOnClose() {} // switch по #state — последние три строки таблицы
  #handleInput(line) {} // пустая строка, команда или текст
  #runCommand(input) {} // /users, /quit, /help или неизвестная
  #handleServerText(text) {} // decode + switch по message.type
  #send(message) {} // connection.send(encode(message))
}
```

`ui.close()` при закрытии соединения обязателен: `readline` держит ввод
открытым, и без этого процесс клиента не завершится (лабораторная 14).

#### Подготовка

Скопируйте в `chat/test/` файл [tests/client-setup.js](tests/client-setup.js).
В нём:

  `'error ...'`, `'chat you: ...'`;

В этих тестах `TestClient` играет роль **сервера**: читает, что прислал
клиент (`await server.next()`), и сам отправляет ему серверные сообщения

`ui.emit('line', 'текст')`, Ctrl+C — `ui.emit('quit')`.

#### Ступень 1. Вход

Тест: [chat-client-1-join.test.js](tests/chat-client-1-join.test.js).

- `run()` сразу отправляет `join`;

  и `printInfo('Online (<число>): <ники через запятую и пробел>')`;

  и закрыть соединение; при закрытии — код 1.

#### Ступень 2. Сообщения

Тест: [chat-client-2-messages.test.js](tests/chat-client-2-messages.test.js).

- ввод: строка из одних пробелов — игнорировать. Иначе `validateText` (та же
  проверка, что на сервере): при проблеме `printError(problem)` и ничего
  не отправлять, иначе `ClientMessage.msg(line)`;
- `msg` → `printChat({ ...message, isOwn: message.from === nick })`;
- `system` → `printSystem(text, ts)`, `users` → `printInfo('Online (...)')`;
- `error` в состоянии `joined` → `printError(message)`;
- строку не удалось разобрать `decode` → `printError('Received a malformed message from the server')`;
- неизвестный `type` — молча пропустить: так старый клиент не сломается,
  если у сервера появятся новые сообщения.

#### Ступень 3. Команды

Тест: [chat-client-3-commands.test.js](tests/chat-client-3-commands.test.js).

Строка, которая начинается с `/`, — команда. Её имя — первое слово:
`input.split(/\s+/)[0]`.

| команда   | действие                                                                                               |
| --------- | ------------------------------------------------------------------------------------------------------ |
| `/users`  | отправить `ClientMessage.list()`; ответ `users` напечатает код из ступени 2                            |
| `/help`   | `printInfo(HELP)`                                                                                      |
| `/quit`   | `quit()`                                                                                               |
| остальные | `printError('Unknown command <имя>. Type /help for the list of commands')`, на сервер ничего не уходит |

Список участников клиент не хранит: `/users` каждый раз спрашивает сервер,
поэтому список всегда актуален.

Для `/quit` уже на этой ступени нужен настоящий `quit()`: если состояние
не `leaving` и не `failed`, перейти в `leaving`, отправить
`ClientMessage.leave()` и закрыть соединение. А при закрытии в `leaving` —
`printInfo('Bye!')` и код 0. Остальные строки таблицы про выход — в ступени 4.

### Шаг 2. Точка входа клиента: `client.js`

Устройство такое же, как у `server.js` (лабораторные 2, 3 и 13): функция `main()`
и её вызов в конце файла.

1. Разобрать `--host`, `--port`, `--nick` и `--transport` (по умолчанию `ws`)
   через `lib/cli.js`. При `UsageError` — сообщение, usage и код 1. Usage
   показывает правило для ника (`NICK_RULES`) и пример:

   ```
   Usage: node client.js --host <address> --port <1-65535> --nick <nickname> [--transport ws|tcp]
     nickname: 1-20 characters: latin letters, digits, "_" or "-"
   Example: node client.js --host 192.168.1.10 --port 5000 --nick alice
   ```

   Ник проверяется `isValidNick` ещё до подключения: незачем ехать
   к серверу с заведомо плохим ником.

2. Подключиться: `await getTransport(name).connect({ host, port })` в `try/catch`.
   При ошибке — `Cannot connect to <host>:<port>: <describeConnectError(error)>`
   (функция из `lib/errors.js`, лабораторная 10) и код 1. При успехе —
   `Connected to <connection.remoteAddress>`.
3. Создать `new TerminalUI()` и `new ChatClient({ connection, ui, nick })`.
4. `process.once('SIGINT', () => client.quit())`. В терминале Ctrl+C перехватывает
   `readline` (это событие `quit` интерфейса), а этот обработчик нужен,
   когда ввод не из терминала (лабораторная 14).
5. `process.exitCode = await client.run()`. Никакого `process.exit()`.

**Проверка:**

| команда                                                    | результат                                                 | код |
| ---------------------------------------------------------- | --------------------------------------------------------- | --- |
| `node client.js --host 127.0.0.1 --port 5000`              | `Error: Option --nick is required` и usage                | 1   |
| `node client.js --host 127.0.0.1 --port 5000 --nick "a b"` | `Error: Invalid nickname "a b"` и usage                   | 1   |
| то же с `--nick ann`, сервер не запущен                    | `Cannot connect to 127.0.0.1:5000: connection refused...` | 1   |
| `--nick ann` при запущенном сервере, затем `/quit`         | `Connected to ...`, приветствие, `Bye!`                   | 0   |
| `--nick ann`, затем остановить сервер                      | `Connection to server lost`                               | 1   |

Полная строка третьего случая:
`Cannot connect to 127.0.0.1:5000: connection refused. Is the server running on this host and port?`
