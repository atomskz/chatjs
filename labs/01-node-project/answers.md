# Лабораторная 1. Ответы

Сначала ответьте сами и проверьте запуском, потом сверяйтесь.

## Разминки

### Разминка 1

1. `Error [ERR_MODULE_NOT_FOUND]: Cannot find module '.../math' ... Did you mean to import "./math.js"?`
   ES-модули не подбирают расширение: файла с именем ровно `math` нет.
2. `SyntaxError: The requested module './math.js' does not provide an export named 'Sum'`.
   Имена чувствительны к регистру, а модуль экспортирует `sum`. Программа
   даже не начнёт выполняться: импорты проверяются до запуска кода.
3. `ReferenceError: require is not defined in ES module scope, you can use import instead`.
   `require` — из старого формата CommonJS, в ES-модулях его нет.
   Правильно: `import fs from 'node:fs'`.
4. `SyntaxError: Cannot use import statement outside a module`, а перед ней
   подсказка Node.js: `Make sure to set "type": "module" in the nearest package.json`.
   С `"commonjs"` файл `.js` читается как CommonJS, где `import` не бывает.

### Разминка 2

1. `npm ci`. Она ставит пакеты строго по `package-lock.json` — ровно те
   версии, что у вас. `npm install` тоже поставит, но может выбрать более
   новые версии в пределах `^`, если lock-файла нет.
2. 8.25.1 — да: `^` разрешает любые новые версии внутри мажорной 8.
   9.0.0 — нет: смена первой цифры означает возможные несовместимые изменения.
3. В `eslint.config.js` нет `globals: globals.node`. ESLint не знает, что
   `process` и `console` — встроенные имена Node.js, и считает их
   необъявленными переменными (правило `no-undef`).

## Контрольные вопросы

1. Имя, версию, тип модулей, нужную версию Node.js, скрипты и список
   зависимостей. Сами пакеты не хранят, потому что их всегда можно скачать
   по этому списку, а `node_modules/` большая и зависит от системы.
2. `dependencies` нужны программе для работы (`ws`), `devDependencies` —
   только разработчику: линтер, форматтер, инструменты тестов. На сервер,
   где программа просто работает, вторые можно не ставить.
3. `package-lock.json` фиксирует точные версии всех пакетов, и `npm ci`
   поставит у любого человека ровно то же самое. `node_modules/` огромна,
   восстанавливается по lock-файлу и может отличаться на разных системах.
4. Файлы `.js` в проекте считаются ES-модулями: работают `import`/`export`,
   а `require`, `__dirname`, `__filename` недоступны.
5. ES-модули ищут файл ровно по написанному пути и не подбирают расширение.
   Файла `./math` нет, есть `./math.js`.
6. Именованных экспортов может быть много, их импортируют в `{}` под тем же
   именем (или переименовывают через `as`). Экспорт по умолчанию — один,
   его импортируют без скобок под любым именем.
7. Префикс гарантирует, что загрузится встроенный модуль Node.js, а не
   пакет из `node_modules` с таким же именем. И сразу видно, что это
   встроенный модуль. Некоторые модули (`node:test`) есть только с префиксом.
8. ESLint находит ошибки смысла: неиспользуемые переменные, опечатки
   в именах. Prettier наводит единое оформление и избавляет от споров
   о пробелах. Задачи разные: Prettier не найдёт опечатку, ESLint не станет
   выравнивать отступы. Нужны оба.
