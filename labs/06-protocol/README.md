# Лабораторная 6. JSON и протокол сообщений

**Цель:** научиться описывать прикладной протокол: формат сообщений,
их создание и разбор, проверку недоверенных данных. Разобраться,
что JSON умеет и чего не умеет, как работают регулярные выражения
и что на самом деле значит «длина строки».

**Понадобится:** лабораторная 3 (классы ошибок). Упражнения делайте в папке
`sandbox-06` с `"type": "module"`, шаг проекта — в `chat/`.

**Примерное время:** 2 часа.

## Теория

### Что такое протокол

Сеть передаёт байты или строки. Чтобы сервер и клиент понимали друг
друга, нужна договорённость: какие бывают сообщения, какие в них поля
и что делать с неправильными. Эта договорённость и есть **прикладной
протокол**. Удобно держать его в одном модуле, общем для сервера
и клиента. Тогда стороны не разойдутся в формате.

Протокол ничего не знает о сети. Он превращает объект в строку и обратно,
а как строка доедет до собеседника — забота транспорта (лабораторные 10–13).

### JSON

```js
JSON.stringify({ type: 'msg', text: 'hi' }); // '{"type":"msg","text":"hi"}'
JSON.parse('{"type":"msg","text":"hi"}'); // { type: 'msg', text: 'hi' }
```

JSON — это не JavaScript. Чего в нём нет:

| значение              | после `JSON.stringify`                      |
| --------------------- | ------------------------------------------- |
| `undefined` в объекте | поле пропадает                              |
| `undefined` в массиве | `null`                                      |
| функция               | поле пропадает                              |
| `NaN`, `Infinity`     | `null`                                      |
| `Date`                | строка ISO; после `parse` это уже не `Date` |
| `BigInt`              | `TypeError`                                 |

`JSON.parse` выбрасывает `SyntaxError` на любой ошибке: одинарные кавычки,
висячая запятая, пустая строка. И он прекрасно разбирает не только объекты:
`'null'`, `'42'`, `'"hi"'` и `'[1,2]'` — тоже правильный JSON.

Перевод строки внутри значения `JSON.stringify` записывает как `\n`
(два символа). Поэтому в закодированном JSON настоящего перевода строки
не бывает. Это пригодится в лабораторной 11.

### Данным из сети доверять нельзя

Подключиться к серверу может кто угодно и прислать что угодно. Значит,
каждое входящее сообщение проверяется:

1. это правильный JSON?
2. это объект? Не `null`, не массив, не число (`typeof null === 'object'`!)
3. есть ли строковое поле `type`?
4. знаем ли мы такой `type`?
5. правильные ли поля у этого типа?

Шаги 1–3 — общая форма, их делает `decode`. Шаги 4–5 зависят от
сообщения, их делает тот, кто его обрабатывает.

### Поле `type` и конструкторы сообщений

Все сообщения — объекты с полем `type`, по которому их различают
(`switch (message.type)`). Чтобы формат каждого сообщения был записан
ровно в одном месте, их создают функциями:

```js
export const ServerMessage = {
  welcome: (users) => ({ type: 'welcome', users }),
  msg: (from, text, ts = Date.now()) => ({ type: 'msg', from, text, ts }),
};

send(ServerMessage.welcome(['ann', 'bob'])); // а не { type: 'welcom', user: [...] } вручную
```

Коды ошибок — тоже константы, а не строки, разбросанные по коду:
`ErrorCode.NICK_TAKEN`.

### Регулярные выражения

```js
const NICK_PATTERN = /^[A-Za-z0-9_-]{1,20}$/;
NICK_PATTERN.test('alice'); // true
```

| часть           | значит                                           |
| --------------- | ------------------------------------------------ |
| `^` и `$`       | начало и конец строки                            |
| `[A-Za-z0-9_-]` | один символ из набора: латиница, цифры, `_`, `-` |
| `{1,20}`        | от 1 до 20 раз                                   |
| `\d`, `\s`      | цифра, пробельный символ                         |

Без `^` и `$` выражение ищет совпадение **где угодно** в строке:
`/[a-z]{1,20}/.test('!!! a !!!')` — `true`.

### Длина строки

Строки в JavaScript хранятся в UTF-16, и `.length` считает 16-битные
единицы, а не символы:

| текст        | `.length` | `[...text].length` | что видит человек | байт в UTF-8 |
| ------------ | --------- | ------------------ | ----------------- | ------------ |
| `hello`      | 5         | 5                  | 5                 | 5            |
| `привет`     | 6         | 6                  | 6                 | 12           |
| `😀`         | 2         | 1                  | 1                 | 4            |
| `👨‍👩‍👧` (семья) | 8         | 5                  | 1                 | 18           |

- `[...text]` разбивает строку на code points: так считать символы честнее.
- Символ, который видит человек (графема), может состоять из нескольких
  code points. Графемы считает `Intl.Segmenter`:
  `[...new Intl.Segmenter().segment(text)].length`.
- Одна и та же буква бывает записана по-разному: `é` — один code point
  (U+00E9) или два: `e` и знак ударения (U+0301). Выглядят одинаково,
  но `'\u00e9' === 'e\u0301'` — `false`. Привести строку к одной форме
  можно через `text.normalize('NFC')`.
- Байты в UTF-8 считает `Buffer.byteLength(text)`. Это важно для сети
  (лабораторная 11).

## Упражнения

Решения лежат в [solution/](solution/).

### Упражнение 1. Пределы JSON

Предскажите, во что `JSON.stringify` превратит объекты из таблицы выше
и строку с `\n` внутри, а затем проверьте. Попробуйте разобрать
`'{"a":1}'`, `"{'a':1}"`, `'{"a":1,}'`, `''`, `'null'`, `'[1,2]'`, `'"hi"'`.
Что из этого — правильный JSON?

### Упражнение 2. Безопасный разбор

Напишите `safeParseMessage(text)`. Она никогда не выбрасывает исключений
и возвращает `{ ok: true, value }` или `{ ok: false, error }`. Сообщение
правильное, если это JSON-объект со строковым полем `type`. Проверьте
на `'{"type":"msg","text":"hi"}'`, `'hello'`, `'null'`, `'[1]'`, `'42'`,
`'{"text":"hi"}'` и `'{"type":5}'`. Правильное здесь только первое.

### Упражнение 3. Проверка ника

Напишите `isValidNick(nick)`: от 1 до 20 символов, латинские буквы, цифры,
`_` и `-`. Составьте таблицу случаев `[значение, ожидание]` и прогоните
её в цикле. Обязательно проверьте пустую строку, 20 и 21 символ, пробел,
кириллицу, `'ann\n'`, число и `null`.

### Упражнение 4. Сколько символов в строке

Для строк `'hello'`, `'привет'`, `'😀'`, `'e\u0301'` (e и отдельный знак ударения)
и `'👨‍👩‍👧'` выведите `.length`, `[...text].length`, число графем
и число байт в UTF-8. Каким способом лучше проверять ограничение
«не длиннее 1000 символов»?

## Шаг проекта

Создайте в проекте `protocol.js` — общий модуль сервера и клиента:

- `MAX_TEXT_LENGTH = 1000`, `NICK_RULES` — правило для ника текстом
  (для сообщений об ошибках);
- `ErrorCode` — объект с кодами `BAD_MESSAGE`, `UNKNOWN_TYPE`, `NOT_JOINED`,
  `ALREADY_JOINED`, `INVALID_NICK`, `NICK_TAKEN`, `INVALID_TEXT`,
  `INTERNAL_ERROR`;
- `class ProtocolError extends Error` с конструктором `(code, message)`,
  полями `name = 'ProtocolError'` и `code`. Порядок аргументов важен:
  сервер будет пересылать клиенту `error.code` и `error.message`;
- `ClientMessage` (`join`, `msg`, `list`, `leave`) и `ServerMessage`
  (`welcome`, `error`, `msg`, `system`, `users`) — конструкторы сообщений
  по таблицам из раздела 5 ТЗ;
- `encode(message)` и `decode(text)`. Если форма неверна, `decode`
  выбрасывает `ProtocolError` с кодом `BAD_MESSAGE`;
- `isValidNick(nick)` — `true`, если это строка по правилу из упражнения 3;
- `validateText(text)` — возвращает `null`, если текст в порядке, или
  описание проблемы (эти тексты проверяют тесты эталона):

  | вход                                                 | результат                                  |
  | ---------------------------------------------------- | ------------------------------------------ |
  | не строка, пустая строка или одни пробелы (`trim()`) | `'Message must not be empty'`              |
  | длиннее `MAX_TEXT_LENGTH` символов (code points)     | `'Message is longer than 1000 characters'` |
  | остальное                                            | `null`                                     |

  Проверку на строку делайте первой: `[...text]` для `undefined`
  выбросит исключение.
