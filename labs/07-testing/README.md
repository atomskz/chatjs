# Лабораторная 7. Автотесты: `node:test`

**Цель:** научиться писать автотесты встроенными средствами Node.js:
проверять обычные и асинхронные функции, ожидаемые исключения и события;
готовить и убирать окружение теста; запускать тесты одной командой.

**Понадобится:** лабораторные 2, 4, 5 и 6. Упражнения 1 и 2 пишите сразу
в проекте `chat/`, в папке `test/`: они проверяют ваши `lib/cli.js`
и `protocol.js`. Упражнения 3 и 4 — в песочницах `sandbox-04` и `sandbox-05`,
рядом с тем кодом, который проверяют.

**Примерное время:** 3–4 часа, два занятия.

**Как работать:** каждый пример запускайте у себя и сверяйте вывод.
В разминках сначала запишите **свой** ответ, потом проверьте и только
потом смотрите [answers.md](answers.md).

## Занятие 1. Первый тест

### 1.1. Зачем

Вы написали `parsePort`, проверили его руками на пяти значениях — работает.
Через неделю поправили одну строку. Работает ли он до сих пор? Чтобы узнать,
придётся снова проверять руками все пять значений. А через месяц функций
будет двадцать.

**Тест** — это программа, которая проверяет другую программу. Он запускается
за секунды и делает то, что руками пришлось бы перепроверять после каждой
правки.

**Аналогия: контроль качества на заводе.** Каждую деталь проверяет автомат
по одним и тем же меркам. Если деталь не прошла — её не пропустят дальше,
и видно, какая мерка не сошлась. Тесты — такие мерки для кода.

Главная польза тестов — смелость: можно переписать модуль и через секунду
узнать, что ничего не сломалось.

### 1.2. Разобранный пример: от `console.log` к тесту

Есть модуль:

```js
// math.js
export function sum(a, b) {
  return a + b;
}
```

**Шаг 1. Проверка глазами.** `console.log(sum(2, 3))` печатает `5`, и вы
смотрите: правильно ли. Каждый раз смотреть приходится самому.

**Шаг 2. `assert` — проверка, которая сама кричит.** `assert.equal(a, b)`
молча проходит, если `a === b`, и **выбрасывает исключение**, если нет:

```js
import assert from 'node:assert/strict';
import { sum } from './math.js';

assert.equal(sum(2, 3), 5);
console.log('first check passed');
assert.equal(sum(2, 2), 5);
console.log('never printed');
```

```
first check passed

AssertionError [ERR_ASSERTION]: Expected values to be strictly equal:

4 !== 5

  actual: 4,
  expected: 5,
```

`actual` — что получилось, `expected` — что ожидали. Смотреть глазами
больше не нужно: если проверка не прошла, программа сама об этом сообщит.

**Шаг 3. Тест.** Проверки складывают в файл `*.test.js` и заворачивают
в `test(имя, функция)`. Каждый тест выполняется отдельно, и падение одного
не мешает остальным:

```js
// test/math.test.js
import assert from 'node:assert/strict';
import { test } from 'node:test';
import { sum } from '../math.js';

test('adds two numbers', () => {
  assert.equal(sum(2, 3), 5);
});

test('adds negative numbers', () => {
  assert.equal(sum(-2, -3), -5);
});
```

```
$ node --test
✔ adds two numbers (0.4273ms)
✔ adds negative numbers (0.0743ms)
ℹ tests 2
ℹ pass 2
ℹ fail 0
```

**Шаг 4. Сломайте код** — замените в `sum` `+` на `-` — и запустите снова.
Тесты упадут, и `node:test` покажет, какой тест, какая проверка, что ждали
и что получили. Как читать такой вывод по шагам — в лабораторной 8,
раздел 2.2.

Тест считается упавшим, если внутри него выброшено исключение. Проверки
`assert` как раз выбрасывают исключение, когда условие не выполнено.

### 1.3. Проверки `assert`

```js
import assert from 'node:assert/strict'; // именно strict
```

| проверка                            | что проверяет                                |
| ----------------------------------- | -------------------------------------------- |
| `assert.equal(a, b)`                | `a === b`                                    |
| `assert.deepEqual(a, b)`            | объекты или массивы совпадают по содержимому |
| `assert.ok(value)`                  | значение истинно                             |
| `assert.match(text, /re/)`          | строка подходит под регулярное выражение     |
| `assert.throws(fn, expected)`       | `fn()` выбрасывает подходящую ошибку         |
| `await assert.rejects(p, expected)` | промис отклоняется подходящей ошибкой        |

- `equal` для объектов не подходит: два разных объекта с одинаковым содержимым
  не равны по `===`. Будет `Values have same structure but are not reference-equal`.
  Для объектов и массивов — `deepEqual`.
- `node:assert/strict` важнее, чем кажется: в нём `equal` сравнивает
  через `===`. В нестрогом `node:assert` проверка `assert.equal(1, '1')` проходит.
- Последним аргументом любой проверки можно передать текст. Он напечатается,
  если проверка не прошла, — удобно в цикле, чтобы видеть, на каком значении
  упало: `assert.equal(isValidNick(nick), false, nick)`.

### 1.4. Проверка ошибок

Ошибка — тоже результат, и её тоже нужно проверять: «на `'abc'` функция
должна выбросить `UsageError`».

```js
assert.throws(() => parsePort('abc'), UsageError);
```

**Обязательно передайте функцию** (`() => parsePort('abc')`), а не результат
вызова (`parsePort('abc')`). Без стрелки `parsePort` выполнится **до**
`assert.throws`, исключение вылетит раньше, чем проверка успеет его поймать,
и тест упадёт с этой ошибкой.

Второй аргумент — какую ошибку ждём:

- класс — `assert.throws(fn, UsageError)`;
- объект с ожидаемыми полями — `{ code: 'ETIMEDOUT' }`;
- регулярное выражение для `message` — `/longer/`;
- функция-проверка: получает ошибку и возвращает `true`, если она подходит.

Если нужно проверить **и класс, и текст**, нужна функция:

```js
assert.throws(
  () => requireOption({}, 'port'),
  (error) => error instanceof UsageError && error.message === 'Option --port is required',
);
```

Объект `{ name: 'UsageError', message: '...' }` здесь не сработает: класс
`class UsageError extends Error {}` из лабораторной 2 не задаёт `name`,
и у его ошибок `name` равно `'Error'`. К тому же объект не проверяет класс.

### 1.5. Много случаев: таблицы и группы

Однотипные случаи удобно описать массивом и создать тесты в цикле:

```js
for (const input of ['0', '65536', 'abc', '']) {
  test(`rejects "${input}"`, () => {
    assert.throws(() => parsePort(input), UsageError);
  });
}
```

Каждое значение — отдельный тест с понятным именем: упадёт ровно тот,
на котором ошибка. Связанные тесты объединяют в группу `describe`:

```js
import { describe, test } from 'node:test'; // it — то же самое, что test

describe('parsePort', () => {
  test('accepts 5000', () => {
    assert.equal(parsePort('5000'), 5000);
  });
  test('rejects 0', () => {
    assert.throws(() => parsePort('0'), UsageError);
  });
});
```

### 1.6. Запуск

```bash
node --test                          # найти и запустить *.test.js и тесты в папке test/
node --test "test/**/*.test.js"      # только файлы по шаблону
node --test test/math.test.js        # один файл
node --test --watch                  # перезапускать при изменении файлов
node --test --test-timeout=10000     # упавший по таймауту тест не повесит весь прогон
```

Шаблон в кавычках раскрывает сам Node.js, поэтому команда одинаково
работает в bash и в PowerShell. В `package.json` её кладут в скрипт `test`
и запускают через `npm test`.

Если Node.js не нашёл ни одного теста, он не ругается, а просто печатает
`ℹ tests 0`. Значит, файл назван не по шаблону (`math.tests.js`,
`mathTest.js`) или лежит не там.

## Занятие 2. Асинхронные тесты, хуки и время

### 2.1. Асинхронные тесты

Если функция теста `async`, `node:test` дождётся её промиса:

```js
test('delay resolves with the value', async () => {
  assert.equal(await delay(10, 'hi'), 'hi');
});

test('withTimeout rejects a slow promise', async () => {
  await assert.rejects(withTimeout(delay(1000), 20), { code: 'ETIMEDOUT' });
});
```

**Забытый `await`** перед `assert.rejects` — частая ошибка: тест закончится
раньше, чем проверка выполнится, и сам тест покажет ✔. Дальше два варианта:

- если проверка не прошла бы, `node:test` позже напишет «generated
  asynchronous activity after the test ended...» с текстом ошибки и отметит
  весь файл как упавший;
- если прошла бы — никакого сообщения не будет. Тест «зелёный», но на самом
  деле ничего не проверял, и сломанный код он тоже пропустил бы.

Увидели «asynchronous activity after the test ended» — ищите пропущенный `await`.

### 2.2. Подготовка и уборка: хуки

**Зачем.** Многим тестам нужно одно и то же: создать объект, запустить
сервер. И после каждого теста нужно убрать за собой — остановить сервер,
таймер. Иначе тесты влияют друг на друга, а прогон «зависает» в конце.

**Разобранный пример: порядок хуков.**

```js
import { after, afterEach, before, beforeEach, describe, test } from 'node:test';

describe('suite', () => {
  before(() => console.log('before (once)'));
  beforeEach(() => console.log('  beforeEach'));
  afterEach(() => console.log('  afterEach'));
  after(() => console.log('after (once)'));
  test('first', () => console.log('    test 1'));
  test('second', () => console.log('    test 2'));
});
```

```
before (once)
  beforeEach
    test 1
  afterEach
  beforeEach
    test 2
  afterEach
after (once)
```

- `beforeEach` / `afterEach` — перед и после **каждого** теста в группе;
- `before` / `after` — один раз на всю группу;
- `afterEach` и `after` выполняются, **даже если тест упал** — поэтому уборку
  пишут в них, а не в конце теста.

Типичное применение:

```js
describe('Ticker', () => {
  let ticker;
  beforeEach(() => {
    ticker = new Ticker(); // свежий объект для каждого теста
  });
  afterEach(() => {
    ticker.stop(); // таймер не переживёт тест, даже упавший
  });
  test('emits ticks', async () => {
    /* ticker уже создан */
  });
});
```

Уборку для одного конкретного теста регистрируют через `t.after`. `t` — объект
текущего теста, его передают первым аргументом:

```js
test('uses a temporary server', async (t) => {
  const server = await startServer();
  t.after(() => server.stop()); // выполнится после этого теста при любом исходе
  // ...
});
```

### 2.3. Фиктивное время

Тест `delay(60_000)` не должен ждать минуту. Для этого таймеры подменяют:

```js
test('waits a minute', async (t) => {
  t.mock.timers.enable({ apis: ['setTimeout'] }); // с этого места setTimeout — поддельный
  const promise = delay(60_000, 'done');
  t.mock.timers.tick(60_000); // «перемотать» время: таймер срабатывает сразу
  assert.equal(await promise, 'done'); // промис всё равно нужно дождаться
});
```

`tick()` синхронный: он вызывает сработавшие таймеры, но промисы выполняются
чуть позже, поэтому `await` остаётся. После теста подмена снимается сама.

### 2.4. Что и как тестировать

Тестируйте **поведение через публичный интерфейс**: «на вход `'abc'` —
ошибка `UsageError`», а не «внутри вызывается регулярное выражение».
Тогда тест не придётся переписывать при каждом рефакторинге.

Хороший тест читается в три шага — **подготовка, действие, проверка**:

```js
test('leave removes the member', () => {
  const room = new Room(); // подготовка
  room.join('ann');

  const removed = room.leave('ann'); // действие

  assert.equal(removed, true); // проверка
  assert.deepEqual(room.list(), []);
});
```

Тесты не должны зависеть друг от друга: каждый готовит себе всё сам
(или в `beforeEach`). Тогда любой тест можно запустить отдельно, и порядок
запуска ничего не меняет.

## Типичные ошибки

| что видите                                               | почему                                               | что делать                                           |
| -------------------------------------------------------- | ---------------------------------------------------- | ---------------------------------------------------- |
| `ℹ tests 0`                                              | файл назван не по шаблону или лежит не там           | `*.test.js` в `test/`; проверить шаблон в `npm test` |
| вспомогательный файл запускается как тест                | `node --test` без шаблона берёт всё из папки `test/` | шаблон `"test/**/*.test.js"`                         |
| `Values have same structure but are not reference-equal` | `equal` для объектов или массивов                    | `deepEqual`                                          |
| тест с `assert.throws` упал с той самой ошибкой          | передан результат вызова, а не функция               | `assert.throws(() => fn(), ...)`                     |
| `assert.equal(1, '1')` проходит                          | импорт из `node:assert` вместо `node:assert/strict`  | `import assert from 'node:assert/strict'`            |
| `asynchronous activity after the test ended`             | пропущен `await` перед асинхронной проверкой         | `await assert.rejects(...)`, `await` всех промисов   |
| тест «зелёный», хотя код сломан                          | забытый `await` — проверка не успела выполниться     | `await`; сломать код и убедиться, что тест падает    |
| `test timed out after ...`                               | тест ждёт промис или событие, которое не наступает   | найти, что не случилось; ставить `--test-timeout`    |
| прогон не завершается после последнего теста             | остались сервер, сокет или таймер                    | уборка в `afterEach` / `t.after`                     |
| тест проходит один, но падает вместе с другими           | тесты делят общее состояние                          | свежие объекты в каждом тесте или в `beforeEach`     |
| объект `{ name: 'UsageError' }` в `throws` не совпадает  | `name` у ошибки не задан и равен `'Error'`           | функция-проверка с `instanceof` (1.4)                |
